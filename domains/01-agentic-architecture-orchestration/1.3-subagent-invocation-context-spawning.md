# 1.3 Configure subagent invocation, context passing, and spawning

> [!NOTE]
> **At a glance**
>
> - **Spawning:** the `Task`/`Agent` tool starts subagents, and `allowedTools` must include it.
> - **Context:** subagents inherit nothing and share no memory; pass everything in the prompt.
> - **`AgentDefinition`:** description (selection), system prompt (behaviour), tools (capability) per subagent type.
> - **Forks:** session forking explores divergent approaches from a shared baseline.

## Example

### What a subagent receives

Only its own system prompt and the Agent tool's `prompt` string, with no parent history or tool results. Put findings in the prompt, keeping content separate from metadata.

```python
import json

findings = [
    {
        "claim": "Generative tools cut stock-illustration commissions in 2024",
        "evidence": "Commissions fell 18% year on year",
        "source_url": "https://example.com/report",  # metadata kept apart from content so attribution survives synthesis
        "document_name": None,
        "page": None,
        "published": "2025-03-02",  # dates let the synthesiser tell a conflict from two different years
    },
]

synthesis_prompt = f"""Write a report section from the findings below.
Keep source_url and published with every claim you use.

<findings>
{json.dumps(findings, indent=2)}
</findings>"""  # the prompt string is the only channel: anything not in it does not exist for the subagent
```

### Detect subagent invocation

```python
from claude_agent_sdk import query, ClaudeAgentOptions, AgentDefinition, ToolUseBlock

async for message in query(
    prompt="Use the code-reviewer agent to review this codebase",
    options=ClaudeAgentOptions(
        allowed_tools=["Read", "Glob", "Grep", "Agent"],  # without the Agent tool in this list, delegation cannot happen at all
        agents={
            "code-reviewer": AgentDefinition(
                description="Expert code reviewer.",
                prompt="Analyze code quality and suggest improvements.",
                tools=["Read", "Glob", "Grep"],  # read-only: a reviewer has no reason to edit
            )
        },
    ),
):
    for block in getattr(message, "content", None) or []:
        # Older SDK versions emitted "Task"; current ones emit "Agent"
        if isinstance(block, ToolUseBlock) and block.name in ("Task", "Agent"):
            print(f"Subagent invoked: {block.input.get('subagent_type')}")
    if getattr(message, "parent_tool_use_id", None):
        print("  (running inside subagent)")
```

### Parallel spawning when you implement the tool yourself

If you build your own `spawn_subagent` tool on the Messages API, parallelism means Claude emits several `tool_use` blocks in one response and you run them together, rather than one per turn.

```python
import asyncio


async def run_tool_calls(response, run_subagent) -> list[dict]:
    calls = [b for b in response.content if b.type == "tool_use"]
    outputs = await asyncio.gather(*(run_subagent(c.input) for c in calls))  # concurrent: latency is the slowest call, not the sum
    return [
        {"type": "tool_result", "tool_use_id": c.id, "content": out}
        for c, out in zip(calls, outputs)
    ]
```

## How it works

> [!IMPORTANT]
> **A subagent is a fresh context with a defined role, not a continuation of the parent.** Isolation keeps agents focused but puts context transfer on the caller: the delegation prompt must carry everything needed, in a form that preserves provenance.

1. **Pass context explicitly.** The subagent sees only its system prompt and the `prompt` string; without the findings it may fill gaps from its own knowledge, silently.
2. **Structure findings.** Claim, evidence, `source_url`, `document_name`, `page`, `published` keep content apart from metadata, so "keep source_url with every claim" can be followed and checked.
3. **Keep dates.** `published` lets a downstream agent tell a real conflict from measurements taken in different years.
4. **Tune three levers.** Wrong subagent chosen is a description problem, wrong behaviour a prompt problem, over-reach a tool-list problem.
5. **Detect invocation.** `ToolUseBlock` named `Agent`/`Task` and `parent_tool_use_id` confirm delegation and attribute activity when debugging.
6. **Spawn in parallel.** Several tool calls in one response run concurrently; across turns, latency becomes the sum rather than the maximum.
7. **Give goals, not procedures.** A rigid procedure stops the subagent adapting when the first approach finds nothing.

## Trade-offs

| Choice | Strength | Cost |
| --- | --- | --- |
| Full findings | Keeps attribution and detail | Tokens on every delegation |
| Summary | Cheaper | Loses citations and nuance; use only when provenance is irrelevant |
| Findings in prompt | Explicit and auditable | Limited by prompt size |
| Shared files | Scales to very large inputs | Needs read tools; adds stale-data risk |
| Parallel spawning | Latency is the slowest call | Only for independent sub-tasks; multiplies concurrent token spend |
| Fresh subagent | Cheap, focused, clean | Starts without the baseline |
| Fork of a session | Carries baseline analysis forward ([1.7](1.7-session-state-resumption-forking.md)) | Carries that context's cost; explores alternatives, does not share memory |
| Goal-oriented prompt | Allows adaptation | Less control than a procedure, which fails on unanticipated inputs |

> [!WARNING]
> **Exam traps**
>
> - **"Subagents inherit the coordinator's history, so send a short instruction"** → they do not. Context must be explicit in the prompt.
> - **"Subagents share memory between invocations"** → each invocation starts fresh. Pass prior outputs forward through the coordinator.
> - **"Pass a prose summary of findings"** → attribution is lost. Use structured data separating content from metadata.
> - **"Spawn one subagent per turn to keep it simple"** → adds serial latency. Emit multiple calls in one response for independent work.
> - **"Forget to allow `Task`/`Agent`"** → no subagent can ever be invoked.
> - **"Prescribe step-by-step procedures for consistency"** → removes adaptability. Specify goals and criteria.

## Check yourself

<details>
<summary>A synthesis subagent reports claims found in no source; the delegation said only "synthesise the research." What happened?</summary>

It received none of the findings, since context is not inherited, and generated content from its own knowledge. Include the findings in its prompt.
</details>

<details>
<summary>Citations vanish from final reports even though search results had URLs. Where is the fix?</summary>

Pass findings in a structured format with source metadata beside each claim, and instruct the subagent to retain it.
</details>

<details>
<summary>Three independent searches take three times as long as one. Why?</summary>

They were probably spawned in separate turns. Issue all three delegation calls in one response.
</details>
