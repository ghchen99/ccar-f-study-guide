# 1.3 Configure subagent invocation, context passing, and spawning

## Knowledge of

- The Task tool as the mechanism for spawning subagents, and the requirement that `allowedTools` must include `"Task"` for a coordinator to invoke subagents.
- Subagent context must be explicitly provided in the prompt: subagents do not automatically inherit parent context or share memory between invocations.
- The `AgentDefinition` configuration including descriptions, system prompts, and tool restrictions for each subagent type.
- Fork-based session management for exploring divergent approaches from a shared analysis baseline.

## Skills in

- Including complete findings from prior agents directly in the subagent's prompt (e.g., passing web search results and document analysis outputs to the synthesis subagent).
- Using structured data formats to separate content from metadata (source URLs, document names, page numbers) when passing context between agents to preserve attribution.
- Spawning parallel subagents by emitting multiple Task tool calls in a single coordinator response rather than across separate turns.
- Designing coordinator prompts that specify research goals and quality criteria rather than step-by-step procedural instructions, to enable subagent adaptability.

## Code snippets

### What a subagent receives

Only its own system prompt and the Agent tool's `prompt` string. It does not get the parent's conversation history or tool results. Put the findings in the prompt, and keep content separate from metadata.

```python
import json

findings = [
    {
        "claim": "Generative tools cut stock-illustration commissions in 2024",
        "evidence": "Commissions fell 18% year on year",
        "source_url": "https://example.com/report",  # metadata kept apart from content so attribution survives synthesis
        "document_name": None,
        "page": None,
        "published": "2025-03-02",  # dates let the synthesiser tell a conflict from two different years
    },
]

synthesis_prompt = f"""Write a report section from the findings below.
Keep source_url and published with every claim you use.

<findings>
{json.dumps(findings, indent=2)}
</findings>"""  # the prompt string is the only channel: anything not in it does not exist for the subagent
```

### Detect subagent invocation

```python
from claude_agent_sdk import query, ClaudeAgentOptions, AgentDefinition, ToolUseBlock

async for message in query(
    prompt="Use the code-reviewer agent to review this codebase",
    options=ClaudeAgentOptions(
        allowed_tools=["Read", "Glob", "Grep", "Agent"],  # without the Agent tool in this list, delegation cannot happen at all
        agents={
            "code-reviewer": AgentDefinition(
                description="Expert code reviewer.",
                prompt="Analyze code quality and suggest improvements.",
                tools=["Read", "Glob", "Grep"],  # read-only: a reviewer has no reason to edit
            )
        },
    ),
):
    for block in getattr(message, "content", None) or []:
        # Older SDK versions emitted "Task"; current ones emit "Agent"
        if isinstance(block, ToolUseBlock) and block.name in ("Task", "Agent"):
            print(f"Subagent invoked: {block.input.get('subagent_type')}")
    if getattr(message, "parent_tool_use_id", None):
        print("  (running inside subagent)")
```

### Parallel spawning when you implement the tool yourself

If you build your own `spawn_subagent` tool on the Messages API, parallelism means Claude emits several `tool_use` blocks in one response and you run them together, rather than one per turn.

```python
import asyncio


async def run_tool_calls(response, run_subagent) -> list[dict]:
    calls = [b for b in response.content if b.type == "tool_use"]
    outputs = await asyncio.gather(*(run_subagent(c.input) for c in calls))  # concurrent: latency is the slowest call, not the sum
    return [
        {"type": "tool_result", "tool_use_id": c.id, "content": out}
        for c, out in zip(calls, outputs)
    ]
```

## Commentary: the concepts behind the code

SDK names are illustrative; know the concept, not the exact parameter.

### The design decision

A subagent is a fresh context with a defined role, not a continuation of the parent. Isolation keeps each agent focused and the coordinator's context small, but it moves the burden of context transfer onto the caller: the delegation prompt must carry everything the subagent needs, and it should carry it in a form that preserves provenance. The principle is explicit context passing over implicit sharing.

### Walk-through

- The subagent sees only its system prompt and the `prompt` string of the delegation call. If the web-search results are not pasted into the synthesiser's prompt, the synthesiser has nothing to synthesise and may fill the gap from its own knowledge without any signal that it did so.
- Findings are structured (claim, evidence, `source_url`, `document_name`, `page`, `published`) with content separate from metadata. In free-form summaries, the link between a claim and its source is easily lost during synthesis; structured fields let the instruction "keep source_url with every claim" be followed and checked.
- Keeping `published` with each claim lets a downstream agent distinguish a real conflict between sources from two measurements taken in different years.
- `AgentDefinition` bundles a description (used by the coordinator to choose), a system prompt (role behaviour) and a tool list (capability boundary). Each of the three is a separate lever: wrong choice of subagent is a description problem, wrong behaviour a prompt problem, over-reach a tool-list problem.
- Detecting the invocation (`ToolUseBlock` named `Agent`/`Task`, `parent_tool_use_id`) is about observability: it confirms delegation happened and attributes activity to the right agent when debugging.
- Parallel spawning means several tool calls in one response. Spread across turns, independent subagents run serially and latency becomes the sum rather than the maximum.
- The coordinator prompt states goals and quality criteria; a rigid procedure would stop the subagent from adapting when the first approach finds nothing.

### Trade-offs and alternatives

- **Pass full findings vs a summary:** full findings preserve attribution and detail but cost tokens in every delegation. Summaries are cheaper but lose citations and nuance; use them only when provenance is irrelevant.
- **Pass findings in the prompt vs shared files or memory:** a file-based hand-off can handle very large inputs, but it needs the subagent to have read tools and adds a place for stale data. The prompt is explicit and auditable; files scale better.
- **Parallel vs sequential:** parallel when sub-tasks are independent; sequential when one needs the other's output. Parallelism also multiplies concurrent token spend.
- **Fresh subagent vs fork of a session:** fresh subagents are cheap, focused and clean; a fork carries the baseline analysis forward at the cost of that context (see 1.7). Forking explores alternatives from a shared baseline; it is not a way for subagents to share memory.
- **Goal-oriented vs procedural coordinator prompts:** goals allow adaptation but give less control; procedures give control but fail on unanticipated inputs.

### Exam traps

- "Subagents automatically inherit the coordinator's history, so only send a short instruction": they do not. Rule: context must be explicit in the prompt.
- "Subagents share memory between invocations": each invocation starts fresh. Rule: pass prior outputs forward through the coordinator.
- Passing a prose summary of findings to the synthesiser: attribution is lost. Rule: use structured data that separates content from metadata.
- Spawning subagents one per turn "to keep things simple": adds serial latency. Rule: emit multiple calls in a single response for independent work.
- Forgetting to allow the delegation tool (`Task`/`Agent`) for the coordinator: no subagent can ever be invoked.
- Prescribing exact step-by-step procedures to subagents "for consistency": removes adaptability. Rule: specify goals and criteria.

### Check yourself

- A synthesis subagent produces a report with claims that appear in no source. The coordinator's delegation said only "synthesise the research." What happened? The subagent received none of the findings, since context is not inherited, and generated content from its own knowledge; the findings must be included in its prompt.
- Citations disappear from final reports even though search results contained URLs. Where should the fix go? Pass findings in a structured format with source metadata kept alongside each claim, and instruct the subagent to retain it.
- Three independent searches take three times as long as one. Why? They were probably spawned in separate turns; issue all three delegation calls in one response.
