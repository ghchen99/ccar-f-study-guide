# 1.2 Orchestrate multi-agent systems with coordinator-subagent patterns

## Knowledge of

- Hub-and-spoke architecture where a coordinator agent manages all inter-subagent communication, error handling, and information routing.
- How subagents operate with isolated context: they do not inherit the coordinator's conversation history automatically.
- The role of the coordinator in task decomposition, delegation, result aggregation, and deciding which subagents to invoke based on query complexity.
- Risks of overly narrow task decomposition by the coordinator, leading to incomplete coverage of broad research topics.

## Skills in

- Designing coordinator agents that analyze query requirements and dynamically select which subagents to invoke rather than always routing through the full pipeline.
- Partitioning research scope across subagents to minimize duplication (e.g., assigning distinct subtopics or source types to each agent).
- Implementing iterative refinement loops where the coordinator evaluates synthesis output for gaps, re-delegates to search and analysis subagents with targeted queries, and re-invokes synthesis until coverage is sufficient.
- Routing all subagent communication through the coordinator for observability, consistent error handling, and controlled information flow.

## Code snippets

### Hub-and-spoke coordinator with specialised subagents

Subagents get no `Agent` tool, so they cannot talk to each other or spawn more agents; everything routes through the coordinator.

```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, AgentDefinition, ResultMessage

# Decomposition breadth (step 1) and the gap-check loop (step 4) guard against the "narrow subtasks, correct subagents" failure
COORDINATOR_PROMPT = """You coordinate a research team producing a cited report.
Quality criteria: cover every major sub-area of the topic, cite a source for each claim,
annotate conflicting figures instead of picking one.

1. Decompose the topic into distinct, non-overlapping sub-areas. Check the breadth of
   the topic first; do not narrow to one corner of it.
2. Invoke only the subagents this query needs. A simple factual question does not need
   the full pipeline.
3. Delegate independent searches in parallel (several Agent calls in one response).
4. After synthesis, look for coverage gaps. Re-delegate targeted searches, then re-run
   synthesis, until coverage is sufficient.
Subagents cannot see this conversation: pass them everything they need in their prompt."""

agents = {
    "web-searcher": AgentDefinition(
        description="Finds web sources for one sub-topic and returns claims with source URLs and dates.",  # the coordinator selects subagents from this text
        prompt="Search the web for the assigned sub-topic. Return structured findings only.",
        tools=["WebSearch", "WebFetch"],  # least privilege: only what this role needs
    ),
    "doc-analyzer": AgentDefinition(
        description="Analyses provided documents and extracts claims with page references.",
        prompt="Analyse the assigned documents. Return structured findings only.",
        tools=["Read", "Grep", "Glob"],
    ),
    "synthesizer": AgentDefinition(
        description="Merges supplied findings into a report. Use only after findings exist.",
        prompt="Combine the supplied findings. Preserve source attribution for every claim.",
        tools=["Read"],  # no search tools: synthesis works on what it is given, so gaps surface at the coordinator
    ),
}


async def main():
    async for message in query(
        prompt="Research the impact of AI on creative industries",
        options=ClaudeAgentOptions(
            system_prompt=COORDINATOR_PROMPT,  # sets goals and quality criteria, not a step-by-step script, so subagents can adapt
            allowed_tools=["Agent"],  # "Task" is still accepted as an alias
            agents=agents,
        ),
    ):
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)


asyncio.run(main())
```

## Commentary: the concepts behind the code

SDK names are illustrative; know the concept, not the exact parameter.

### The design decision

In a multi-agent system, one agent (the coordinator) owns decomposition, delegation, aggregation and error handling, and specialised subagents never talk to each other. Centralising control gives one place for observability, consistent error policy and information-flow control. It also makes the coordinator the single point where quality is decided: a subagent can only be as complete as the task it was given.

### Walk-through

- Subagents get no `Agent` tool and receive only their own prompt. This enforces hub-and-spoke structurally: they cannot spawn further agents or exchange results sideways, so every hand-off is visible to the coordinator.
- The coordinator prompt states quality criteria (breadth, citations, conflicting figures annotated) rather than a procedure. Subagents then adapt to what they find, while the coordinator still has a standard to judge their output against.
- Step 1 ("check the breadth of the topic first") targets the characteristic failure in sample question 7: every subagent succeeds, yet the report covers only visual arts because the coordinator split "creative industries" into three visual subtasks. Nothing downstream can repair a gap that was never assigned.
- Step 2 ("invoke only the subagents this query needs") avoids running the full pipeline for a simple factual question, saving cost and latency and reducing the surface for errors.
- Step 3 (parallel `Agent` calls in one response) cuts wall-clock time for independent sub-areas. It only works because the sub-areas were partitioned to be non-overlapping; overlapping scopes would produce duplicate work and redundant citations.
- Step 4 is the iterative refinement loop: evaluate the synthesis for gaps, re-delegate targeted searches, re-synthesise. Without it, coverage is whatever the first decomposition happened to produce.
- Distinct `description` fields matter because the coordinator chooses among subagents using them. Vague or overlapping descriptions produce mis-delegation.
- Per-role `tools` lists apply least privilege: the synthesiser cannot browse the web, so missing evidence shows up as a gap for the coordinator to fill rather than being silently improvised.

### Trade-offs and alternatives

- **Hub-and-spoke vs peer-to-peer subagents:** peer communication can cut round trips, but it removes the coordinator's visibility, makes error handling inconsistent and makes information flow hard to reason about. Hub-and-spoke pays extra coordinator hops for control and traceability.
- **Dynamic subagent selection vs a fixed pipeline:** a fixed pipeline is predictable and easy to test but wastes work on simple queries and cannot skip or repeat stages. Dynamic selection costs a little coordinator reasoning and requires good descriptions.
- **Parallel vs sequential delegation:** parallel is faster but suits only independent sub-areas. If one step needs another's output (search, then synthesise), sequence it.
- **One generalist agent vs several specialists:** specialists give focused prompts and tool sets and isolated context, at the price of coordination overhead and token cost per subagent. For small tasks a single agent is simpler.
- **Refinement loops** improve coverage but cost extra rounds; bound them (a budget or a "sufficient coverage" criterion).

### Exam traps

- Blaming a downstream agent for a coverage gap ("improve the synthesiser's gap detection", "widen the search agent's queries") when the coordinator logs show narrow decomposition. Rule: fix the root cause at the stage that produced it, and read the logs to locate it (sample question 7, answer B).
- "Let subagents share context or message each other directly to avoid duplication": removes the coordinator's control and observability. Rule: route all inter-agent communication through the coordinator.
- "Subagents inherit the parent's conversation, so no need to pass findings": subagent context is isolated. Rule: anything a subagent needs must be in its prompt (see 1.3).
- "Always run every subagent in a fixed order": ignores query complexity. Rule: the coordinator selects subagents dynamically.
- "Give all subagents all tools for flexibility": violates least privilege and blurs roles. Rule: scope tools to the role; add narrowly scoped cross-role tools only when a measured need exists (sample question 9).
- Omitting `Agent` from the coordinator's allowed tools (exam wording: `Task`): the coordinator then cannot delegate at all.

### Check yourself

- A research report on "renewable energy" omits wind power. Search and synthesis agents behaved correctly. Where is the defect, and what is the fix? In the coordinator's decomposition; instruct it to enumerate the full breadth of the topic and add a gap-check loop that re-delegates for missing areas.
- A team lets the web-search subagent call the document-analysis subagent directly to save time. What is lost? Central observability, consistent error handling and controlled information flow, because the coordinator no longer sees or governs that exchange.
- A simple "what year was X founded?" query runs the whole search, analysis and synthesis pipeline. What design change fits? Let the coordinator select only the subagents the query needs, or answer with a single search.

> **Exam wording vs current docs:** the exam guide says `allowedTools` must include `"Task"`. Current SDK docs name the tool `Agent` and keep `Task` as an alias (the init message still lists it as `Task`). Know both.

> **Background default:** per the Python reference, when your main agent calls `Agent` without `run_in_background`, the subagent runs in the background (`status: "async_launched"`) and its report arrives in a later turn; Claude waits when its next step needs the result. A subagent that spawns its own agents waits by default.
