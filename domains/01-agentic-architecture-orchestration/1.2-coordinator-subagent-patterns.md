# 1.2 Orchestrate multi-agent systems with coordinator-subagent patterns

> [!NOTE]
> **At a glance**
>
> - **Hub-and-spoke:** the coordinator owns communication, error handling and routing between subagents.
> - **Isolation:** subagents do not inherit the coordinator's conversation history.
> - **Coordinator role:** decompose, delegate, aggregate, and pick subagents by query complexity.
> - **Main risk:** overly narrow decomposition leaves broad topics partly uncovered.

## Example

### Hub-and-spoke coordinator with specialised subagents

Subagents get no `Agent` tool, so they cannot message each other or spawn agents; everything routes through the coordinator.

```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, AgentDefinition, ResultMessage

# Decomposition breadth (step 1) and the gap-check loop (step 4) guard against the "narrow subtasks, correct subagents" failure
COORDINATOR_PROMPT = """You coordinate a research team producing a cited report.
Quality criteria: cover every major sub-area of the topic, cite a source for each claim,
annotate conflicting figures instead of picking one.

1. Decompose the topic into distinct, non-overlapping sub-areas. Check the breadth of
   the topic first; do not narrow to one corner of it.
2. Invoke only the subagents this query needs. A simple factual question does not need
   the full pipeline.
3. Delegate independent searches in parallel (several Agent calls in one response).
4. After synthesis, look for coverage gaps. Re-delegate targeted searches, then re-run
   synthesis, until coverage is sufficient.
Subagents cannot see this conversation: pass them everything they need in their prompt."""

agents = {
    "web-searcher": AgentDefinition(
        description="Finds web sources for one sub-topic and returns claims with source URLs and dates.",  # the coordinator selects subagents from this text
        prompt="Search the web for the assigned sub-topic. Return structured findings only.",
        tools=["WebSearch", "WebFetch"],  # least privilege: only what this role needs
    ),
    "doc-analyzer": AgentDefinition(
        description="Analyses provided documents and extracts claims with page references.",
        prompt="Analyse the assigned documents. Return structured findings only.",
        tools=["Read", "Grep", "Glob"],
    ),
    "synthesizer": AgentDefinition(
        description="Merges supplied findings into a report. Use only after findings exist.",
        prompt="Combine the supplied findings. Preserve source attribution for every claim.",
        tools=["Read"],  # no search tools: synthesis works on what it is given, so gaps surface at the coordinator
    ),
}


async def main():
    async for message in query(
        prompt="Research the impact of AI on creative industries",
        options=ClaudeAgentOptions(
            system_prompt=COORDINATOR_PROMPT,  # sets goals and quality criteria, not a step-by-step script, so subagents can adapt
            allowed_tools=["Agent"],  # "Task" is still accepted as an alias
            agents=agents,
        ),
    ):
        if isinstance(message, ResultMessage) and message.subtype == "success":
            print(message.result)


asyncio.run(main())
```

## How it works

> [!IMPORTANT]
> **The coordinator owns decomposition, delegation, aggregation and error handling; subagents never talk to each other.** This gives one place for observability and error policy, and a subagent is only as complete as the task it was given.

1. **Enforce the hub structurally.** Subagents get no `Agent` tool and see only their own prompt, so every hand-off is visible to the coordinator.
2. **State criteria, not a procedure.** Breadth, citations and annotated conflicts let subagents adapt while the coordinator keeps a standard to judge output.
3. **Decompose for breadth.** Step 1 targets sample question 7: every subagent succeeds yet the report covers only visual arts, because nothing downstream can repair an unassigned gap.
4. **Select and parallelise.** Invoke only needed subagents (step 2); parallel `Agent` calls (step 3) work because sub-areas are non-overlapping, avoiding duplicate work and citations.
5. **Refine in a loop.** Step 4 checks the synthesis for gaps, re-delegates and re-synthesises; otherwise coverage is whatever the first decomposition produced.
6. **Write distinct descriptions and scope tools.** The coordinator chooses by `description`, so vague text mis-delegates. Per-role `tools` mean missing evidence surfaces as a gap, not an improvisation.

## Trade-offs

| Choice | Strength | Cost |
| --- | --- | --- |
| Hub-and-spoke | Visibility, consistent errors, controlled information flow | Extra coordinator hops |
| Peer-to-peer subagents | Fewer round trips | Coordinator loses visibility; inconsistent error handling |
| Dynamic selection | Skips unneeded stages on simple queries | Coordinator reasoning; needs good descriptions |
| Fixed pipeline | Predictable, easy to test | Wasted work; cannot skip or repeat stages |
| Parallel delegation | Faster for independent sub-areas | Sequence instead when one step needs another's output |
| Specialist subagents | Focused prompts, tools and context | Coordination overhead and tokens; a single agent suits small tasks |
| Refinement loops | Better coverage | Extra rounds; bound with a budget or "sufficient coverage" criterion |

> [!WARNING]
> **Exam traps**
>
> - **"Improve the synthesiser's gap detection" / "widen the search agent's queries"** → blames downstream when logs show narrow decomposition. Fix the root cause at the stage that produced it (sample question 7, answer B).
> - **"Let subagents share context or message each other directly"** → removes control and observability. Route all inter-agent communication through the coordinator.
> - **"Subagents inherit the parent's conversation"** → context is isolated. Anything a subagent needs must be in its prompt (see [1.3](1.3-subagent-invocation-context-spawning.md)).
> - **"Always run every subagent in a fixed order"** → ignores query complexity. The coordinator selects dynamically.
> - **"Give all subagents all tools"** → breaks least privilege. Scope tools to the role; add narrow cross-role tools only for a measured need (sample question 9).
> - **Omitting `Agent` (exam wording: `Task`) from allowed tools** → the coordinator cannot delegate at all.

## Check yourself

<details>
<summary>A report on "renewable energy" omits wind power, though search and synthesis behaved correctly. Where is the defect?</summary>

In the coordinator's decomposition. Have it enumerate the topic's full breadth and add a gap-check loop that re-delegates for missing areas.
</details>

<details>
<summary>The web-search subagent calls the document-analysis subagent directly to save time. What is lost?</summary>

Central observability, consistent error handling and controlled information flow, because the coordinator no longer sees or governs the exchange.
</details>

<details>
<summary>A simple "what year was X founded?" query runs the whole pipeline. What design change fits?</summary>

Let the coordinator select only the subagents the query needs, or answer with a single search.
</details>

> [!TIP]
> **Exam wording vs current docs:** the exam guide says `allowedTools` must include `"Task"`; current SDK docs name the tool `Agent` and keep `Task` as an alias (the init message still lists `Task`). Know both.
>
> **Background default:** per the Python reference, an `Agent` call without `run_in_background` runs the subagent in the background (`status: "async_launched"`) and its report arrives in a later turn; Claude waits when its next step needs it. A subagent that spawns its own agents waits by default.
