# 1.1 Design and implement agentic loops for autonomous task execution

> [!NOTE]
> **At a glance**
>
> - **Lifecycle:** request → inspect `stop_reason` (`tool_use` or `end_turn`) → run tools → return results → repeat.
> - **History:** every tool result is appended so the model can plan its next step.
> - **Control:** the model chooses the next tool; the code does not follow a fixed script.

## Example

### Raw Messages API loop (what the exam's `stop_reason` questions describe)

```python
import anthropic

client = anthropic.Anthropic()
MODEL = "claude-sonnet-5-5"  # any current model ID


def run_agent_loop(user_prompt: str, tools: list[dict], execute_tool) -> str:
    messages = [{"role": "user", "content": user_prompt}]
    while True:  # the model decides when to stop; the loop only reacts to stop_reason
        response = client.messages.create(
            model=MODEL, max_tokens=4096, tools=tools, messages=messages
        )
        # The whole assistant turn, tool_use blocks included, goes back into history
        messages.append({"role": "assistant", "content": response.content})

        if response.stop_reason == "end_turn":
            return "".join(b.text for b in response.content if b.type == "text")

        if response.stop_reason == "tool_use":
            tool_results = [  # parallel tool calls arrive together; answer every one in a single user turn
                {
                    "type": "tool_result",
                    "tool_use_id": block.id,  # pairs each result with its request; a mismatch is an API error
                    "content": execute_tool(block.name, block.input),
                }
                for block in response.content
                if block.type == "tool_use"
            ]
            # Results go back as a user turn so Claude reasons over them next
            messages.append({"role": "user", "content": tool_results})
            continue

        raise RuntimeError(f"Unhandled stop_reason: {response.stop_reason}")  # e.g. max_tokens
```

### Anti-patterns

```python
for _ in range(10):                               # arbitrary cap as the primary stop condition: cuts off legitimate long tasks, wastes turns on short ones
    ...
if "I'm done" in response.content[0].text: ...    # parsing natural language for termination: phrasing varies, so it is brittle
if response.content[0].type == "text": break      # text can accompany tool_use blocks, so this exits mid-task
```

### Agent SDK: the loop is run for you

The SDK runs the same tool_use / tool_result cycle internally. You consume messages and read the final `ResultMessage`. `max_turns` and `max_budget_usd` are safety limits, not the normal stop mechanism.

```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage, ResultError


async def main():
    try:
        async for message in query(
            prompt="Find and fix the failing tests in the auth module",
            options=ClaudeAgentOptions(
                allowed_tools=["Read", "Edit", "Bash", "Glob", "Grep"],
                max_turns=30,  # backstop against runaway loops; hitting it is a failure to investigate, not a normal exit
            ),
        ):
            if isinstance(message, ResultMessage):
                if message.subtype == "success":
                    print(message.result)
                else:  # error_max_turns, error_max_budget_usd, error_during_execution
                    print(f"Stopped: {message.subtype}")  # distinguish "finished" from "cut off" before trusting the output
    except ResultError as error:  # SDK 0.2.140+: raised after an error result is yielded
        print(f"Ended with {error.terminal_reason or error.subtype}: {error}")


asyncio.run(main())
```

## How it works

> [!IMPORTANT]
> **The model drives; the harness reacts.** Read the structured signal (`stop_reason`) for "I want a tool" versus "I'm finished". Never infer it from prose or an iteration count.

1. **Append the whole assistant turn**, `tool_use` blocks included, so each `tool_result` has a matching request.
2. **Answer every tool call** in one user turn. Each `tool_result` echoes its `tool_use_id`; a mismatch is a protocol error.
3. **Let the model choose next.** Results return as fresh evidence; no tool sequence is scripted in code.
4. **Exit only on `end_turn`.** Anything else, such as `max_tokens`, hits the explicit `raise` so truncated output is never returned as complete.
5. **Never exit on text.** A response can hold text ("Let me check that order") and a `tool_use` block together.
6. **In the SDK, check `ResultMessage.subtype`.** `max_turns` and `max_budget_usd` are backstops, and a limit-terminated result may be partial.

## Trade-offs

| Choice | Strength | Cost |
| --- | --- | --- |
| Model-driven loop | Adapts to unexpected results | Path is unpredictable. Add enforcement for must-happen steps ([1.4](1.4-workflow-enforcement-handoff.md), [1.5](1.5-hooks-interception-normalization.md)) |
| Fixed pipeline | Predictable and easy to test | Breaks when the task deviates |
| Iteration cap | Cost control and safety net | As the primary stop it truncates valid work. Treat a hit as an incident |
| Raw Messages API | Full control; matches exam wording | You own history, execution and limits |
| Agent SDK | Removes boilerplate | Less visibility per iteration |

Every iteration also grows history, so trim large tool outputs ([5.1](../05-context-management-reliability/5.1-context-preservation.md)).

> [!WARNING]
> **Exam traps**
>
> - **"Stop after N iterations"** → a cap is not a completion signal. Terminate on `stop_reason`; keep caps as a backstop.
> - **"Parse the reply for 'done'"** → free text drifts. Use the structured field.
> - **"If it contains text, it's finished"** → text can accompany `tool_use`. Check `stop_reason`, not content type.
> - **"Pre-define the tool sequence"** → replaces reasoning with a script. Fix sequences only where the workflow truly is fixed.
> - **"Drop tool results to save tokens"** → the model can't reason about what it learned. Trim them instead.

## Check yourself

<details>
<summary>A loop exits on any text block, and tasks stop after "Let me look that up." What's wrong?</summary>

The response held text plus a `tool_use` block. Exit on `stop_reason == "end_turn"`, and run the tool.
</details>

<details>
<summary>An agent hits <code>max_turns</code> on 5% of runs. Raise the limit?</summary>

Check first whether those runs are stuck on a failing tool. A higher cap only delays the same failure.
</details>

<details>
<summary>The loop gets <code>stop_reason == "max_tokens"</code> and returns the text. Why is that unsafe?</summary>

The output was truncated and may be incomplete. Handle it explicitly rather than treating it as `end_turn`.
</details>

> [!TIP]
> In the SDK, `stop_reason` surfaces on `AssistantMessage` and `ResultMessage`; `ResultMessage.subtype` / `terminal_reason` say how the run ended. Before SDK 0.2.140 there is no `ResultError`, so catch a generic `Exception`.
