# 1.7 Manage session state, resumption, and forking

## Knowledge of

- Named session resumption using `--resume <session-name>` to continue a specific prior conversation.
- `fork_session` for creating independent branches from a shared analysis baseline to explore divergent approaches.
- The importance of informing the agent about changes to previously analyzed files when resuming sessions after code modifications.
- Why starting a new session with a structured summary is more reliable than resuming with stale tool results.

## Skills in

- Using `--resume` with session names to continue named investigation sessions across work sessions.
- Using `fork_session` to create parallel exploration branches (e.g., comparing two testing strategies or refactoring approaches from a shared codebase analysis).
- Choosing between session resumption (when prior context is mostly valid) and starting fresh with injected summaries (when prior tool results are stale).
- Informing a resumed session about specific file changes for targeted re-analysis rather than requiring full re-exploration.

## Code snippets

### Capture the session ID, then resume

```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage

TOOLS = ["Read", "Grep", "Glob"]


async def run(prompt: str, **opts) -> str | None:
    session_id = None
    try:
        async for message in query(prompt=prompt, options=ClaudeAgentOptions(allowed_tools=TOOLS, **opts)):
            if isinstance(message, ResultMessage):
                session_id = message.session_id  # present on success and error results
    except Exception as error:
        print(f"Session ended with an error: {error}")  # single-shot query() raises after an error result
    return session_id


async def main():
    session_id = await run("Analyze the auth module and suggest improvements")

    # Resume when prior context is mostly valid; tell it what changed
    await run(
        "auth/session.py and auth/tokens.py changed since your analysis (expiry moved to config). "
        "Re-read only those two files and update your findings.",
        resume=session_id,
    )


asyncio.run(main())
```

### Fork: two approaches from one shared baseline

Forking copies the history into a new session; the original is untouched. It branches the conversation, not the filesystem, so edits made by a fork are real.

```python
async def compare_approaches(baseline_id: str):
    oauth_id = await run(
        "Outline how OAuth2 would work for the auth module",
        resume=baseline_id, fork_session=True, max_turns=5,
    )
    jwt_id = await run("Continue with the JWT approach", resume=baseline_id)
    return oauth_id, jwt_id
```

Standalone helpers also exist:

```python
from claude_agent_sdk import fork_session, list_sessions, rename_session

forked = fork_session(baseline_id, title="Try the OAuth approach")
rename_session(baseline_id, "auth-investigation")  # human-readable name
```

### Start fresh with an injected summary when tool results are stale

```python
summary = """Prior findings (verified against commit abc123):
- Token refresh lives in auth/tokens.py
- Session store is Redis-backed
The following files have since changed: auth/tokens.py. Re-check only those."""
await run(f"{summary}\n\nNow design the migration plan.")
```

### CLI

```bash
claude --resume auth-investigation   # continue a named session
```

In Python, `ClaudeSDKClient` keeps one session across `client.query()` calls with no ID handling (`async with ClaudeSDKClient(options) as client:`), which suits multi-turn work in a single process. Use `resume=` / `fork_session=True` when IDs must survive across processes. `resume_session_at=<message uuid>` with `fork_session=True`, or `fork_session(session_id, up_to_message_id=...)`, branches from an earlier point.
