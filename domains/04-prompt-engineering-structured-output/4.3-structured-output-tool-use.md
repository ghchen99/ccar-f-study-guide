# 4.3 Enforce structured output using tool use and JSON schemas

## Knowledge of

- Tool use (`tool_use`) with JSON schemas as the most reliable approach for guaranteed schema-compliant structured output, eliminating JSON syntax errors.
- The distinction between `tool_choice`:
  - `"auto"`: model may return text instead of calling a tool
  - `"any"`: model must call a tool but can choose which
  - forced tool selection: model must call a specific named tool
- Strict JSON schemas via tool use eliminate syntax errors but do not prevent semantic errors (e.g., line items that don't sum to total, values in wrong fields).
- Schema design considerations: required vs optional fields, enum fields with "other" + detail string patterns for extensible categories.

## Skills in

- Defining extraction tools with JSON schemas as input parameters and extracting structured data from the `tool_use` response.
- Setting `tool_choice: "any"` to guarantee structured output when multiple extraction schemas exist and the document type is unknown.
- Forcing a specific tool with `tool_choice: {"type": "tool", "name": "extract_metadata"}` to ensure a particular extraction runs before enrichment steps.
- Designing schema fields as optional (nullable) when source documents may not contain the information, preventing the model from fabricating values to satisfy required fields.
- Adding enum values like `"unclear"` for ambiguous cases and `"other"` + detail fields for extensible categorization.
- Including format normalization rules in prompts alongside strict output schemas to handle inconsistent source formatting.

## Code snippets

### Extraction tool with a schema (the exam's `tool_use` approach)

Nullable fields stop the model fabricating values; `"unclear"` and `"other"` + detail handle ambiguity and extensibility.

```python
import anthropic

client = anthropic.Anthropic()
MODEL = "claude-sonnet-5-5"  # forced tool_choice caveat below

extract_invoice = {
    "name": "extract_invoice",
    "description": "Record the structured fields extracted from an invoice document.",
    "input_schema": {
        "type": "object",
        "properties": {
            "invoice_number": {"type": "string"},
            "stated_total": {"type": ["number", "null"], "description": "Total printed on the document; null if absent"},
            "calculated_total": {"type": ["number", "null"], "description": "Sum of line items you computed"},
            "currency": {"type": ["string", "null"], "description": "ISO 4217, e.g. USD; null if not stated"},
            "payment_terms": {
                "type": "string",
                "enum": ["net_30", "net_60", "due_on_receipt", "unclear", "other"],
            },
            "payment_terms_detail": {"type": ["string", "null"], "description": "Required when payment_terms is 'other'"},
            "line_items": {
                "type": "array",
                "items": {
                    "type": "object",
                    "properties": {
                        "description": {"type": "string"},
                        "quantity": {"type": "number"},
                        "unit_price": {"type": "number"},
                    },
                    "required": ["description", "quantity", "unit_price"],
                },
            },
        },
        "required": ["invoice_number", "payment_terms", "line_items"],  # the rest may be null
    },
}

response = client.messages.create(
    model=MODEL,
    max_tokens=2048,
    tools=[extract_invoice],
    tool_choice={"type": "tool", "name": "extract_invoice"},
    system="Normalise dates to ISO 8601 and amounts to plain numbers (no currency symbols). "
           "If a field is not in the document, return null; never guess.",
    messages=[{"role": "user", "content": document_text}],
)
data = next(b.input for b in response.content if b.type == "tool_use")
```

### Choosing `tool_choice`

| Value | Behaviour | Use for |
| - | - | - |
| `{"type": "auto"}` | May answer in text instead of calling a tool | Normal agent turns |
| `{"type": "any"}` | Must call a tool; Claude picks which | Several extraction schemas, document type unknown |
| `{"type": "tool", "name": "extract_metadata"}` | Must call that tool | Run metadata extraction before enrichment steps |

```python
# Unknown document type: guarantee a structured result from one of several schemas
tools = [extract_invoice, extract_receipt, extract_contract]
```

### Newer alternatives in the current API

```python
from pydantic import BaseModel

class ContactInfo(BaseModel):
    name: str
    email: str | None   # nullable when the document may not contain it

response = client.messages.parse(
    model=MODEL, max_tokens=1024,
    output_format=ContactInfo,       # sent as output_config.format (json_schema)
    messages=[{"role": "user", "content": text}],
)
print(response.parsed_output)
```

`strict: true` on a tool definition gives guaranteed schema-valid tool inputs. Notes from [Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs):

- Both eliminate JSON syntax errors via constrained decoding. Neither prevents **semantic** errors (line items not summing to the total, a value in the wrong field).
- Not supported in the schema: `minimum`/`maximum`, `minLength`/`maxLength`, recursive schemas; `additionalProperties` must be `false`.
- Refusals (`stop_reason: "refusal"`) and truncation (`max_tokens`) can yield output that does not match the schema.
- Enum casing is not guaranteed, so compare case-insensitively.
- Forced `any`/`tool` is rejected on some newer models and with manual extended thinking; use `auto` + `strict: true` or `output_config.format` there (see [2.3](../02-tool-design-mcp-integration/2.3-tool-distribution-tool-choice.md)).
