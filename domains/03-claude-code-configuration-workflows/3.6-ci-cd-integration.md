# 3.6 Integrate Claude Code into CI/CD pipelines

> [!NOTE]
> **At a glance**
>
> - **Non-interactive:** `-p` (`--print`) runs one prompt, prints and exits; without it the job hangs.
> - **Structured output:** `--output-format json` with `--json-schema` gives parseable findings.
> - **Context:** CLAUDE.md supplies testing standards, fixture conventions and review criteria to CI runs.
> - **Independence:** a fresh review session beats the session that wrote the code.

## Example

### Non-interactive run: `-p`

```bash
claude -p "Analyze this pull request for security issues"      # processes the prompt, prints, exits
# piping gives the model the exact change under review instead of leaving it to find it
git diff origin/main...HEAD | claude -p "Review this diff for security issues"
```

Without `-p` the job waits for interactive input and hangs. `CLAUDE_HEADLESS` and `--batch` do not exist.

### Machine-parseable findings

```bash
# the schema, not prose, guarantees a parseable shape; a downstream script posts the comments
claude -p "Review the staged changes. Report bugs and security issues only." \
  --output-format json \
  --json-schema '{
    "type": "object",
    "properties": {
      "findings": {
        "type": "array",
        "items": {
          "type": "object",
          "properties": {
            "file": {"type": "string"},
            "line": {"type": "integer"},
            "severity": {"enum": ["critical", "high", "medium", "low"]},
            "issue": {"type": "string"},
            "suggested_fix": {"type": "string"}
          },
          "required": ["file", "line", "severity", "issue"]
        }
      }
    },
    "required": ["findings"]
  }' | jq '.structured_output.findings'
```

The response carries `structured_output`; if the run ends without valid structured output the field is absent, so check before posting inline PR comments.

### Reproducible CI runs

```bash
# --bare skips hooks, skills, MCP, auto memory and CLAUDE.md from the host machine
claude --bare -p "Summarize README.md" --allowedTools "Read"     # needs ANTHROPIC_API_KEY
```

Bare mode skips CLAUDE.md, so avoid it when you want the project's review criteria and test standards, or pass them with `--append-system-prompt-file`. Without `--bare`, `claude -p` loads the project's CLAUDE.md like an interactive session.

### Pre-approve only what the job needs

```bash
# least privilege: an unattended job should hold only the tools its task needs
claude -p "Run the test suite and fix any failures" --allowedTools "Bash,Read,Edit"
claude -p "..." --permission-mode dontAsk   # deny anything not pre-approved; locked-down CI
```

### Context for CI-invoked Claude lives in CLAUDE.md

```markdown
# Testing standards
- Framework: pytest; fixtures in tests/conftest.py (db_session, fake_clock, api_client)
- A valuable test checks behaviour or an edge case, not a getter
- Skip: trivial property tests, tests duplicating existing coverage

# Review criteria
Report: bugs, security issues. Skip: formatting, naming style, minor local patterns.
```

### Re-review after new commits without duplicate comments

```bash
# prior findings in context stop the same comment being posted again on every push
claude -p "Review this diff. Prior findings are below. Report only NEW issues or ones still unaddressed.

<prior_findings>
$(cat prior_findings.json)
</prior_findings>

$(git diff origin/main...HEAD)" --output-format json --json-schema "$SCHEMA"
```

### Test generation without duplicates

```bash
# naming the existing test file lets the model skip covered scenarios instead of regenerating them
claude -p "Generate tests for src/refunds.py. Existing tests are in tests/test_refunds.py; \
do not repeat scenarios already covered." --allowedTools "Read,Write"
```

### Independent reviewer, not the generating session

Run the review as a separate `claude -p` invocation (a new session with no memory of the generation), not by continuing the session that wrote the code, which retains its reasoning and rarely questions its own decisions.

```bash
claude -p "Implement the feature in ISSUE.md"            # session A
claude -p "Review the uncommitted changes" --output-format json   # new session B, no --continue/--resume; fresh context can question the author's choices
```

## How it works

> [!IMPORTANT]
> **A pipeline has no human, so it must run non-interactively, take context from committed config, return parseable output and hold minimal permissions.** Reviews should also come from an independent session and know what earlier runs reported.

1. **Run with `-p`.** It prints and exits; without it the job waits for input and hangs. Plausible-sounding variables or flags that are not part of the tool do nothing.
2. **Constrain output.** `--json-schema` guarantees shape, not truth. A run without valid structured output omits the field, so the script must check before posting.
3. **Keep context in CLAUDE.md.** Criteria stay versioned with the code and shared by every run; bare mode drops them unless passed explicitly. Explicit report/skip lists beat "be thorough" or confidence thresholds.
4. **Apply least privilege.** `--allowedTools` and `dontAsk` deny anything unapproved rather than waiting for a human who is not there.
5. **Pass prior findings and existing tests.** Without them each push re-reports old issues and the bot is ignored, and generation repeats covered scenarios.
6. **Use a fresh reviewer.** Session B has no `--continue` or `--resume`; the author session defends its choices, a new one sees only the output.

## Trade-offs

| Choice | Strength | Cost |
| --- | --- | --- |
| Synchronous CLI | Immediate result for blocking pre-merge checks | Full price |
| Batches API ([4.5](../04-prompt-engineering-structured-output/4.5-batch-processing.md)) | Cheaper | No guaranteed turnaround; suits non-blocking work such as nightly reports |
| Bare mode | Reproducible, independent of host machine | Loses CLAUDE.md; use for generic tasks |
| Structured output | Enables automation | Schema design and validation handling; free text suffices when a human reads it |
| Fresh reviewer session | Independent scrutiny | Another run; self-review is cheaper but systematically weaker |
| Per-file plus integration passes ([4.6](../04-prompt-engineering-structured-output/4.6-multi-pass-review.md)) | Consistent depth on large PRs | More calls |
| Broad tool access | Makes fixes possible | Larger blast radius, including prompt injection via reviewed code; review jobs rarely need write tools |

> [!WARNING]
> **Exam traps**
>
> - **"Set `CLAUDE_HEADLESS=true`" or "add `--batch`"** → non-existent. The documented non-interactive mechanism is `-p`.
> - **"Redirect stdin from `/dev/null`"** → a Unix workaround that ignores how Claude Code is invoked.
> - **"Have the same session that wrote the code review it"** → keeps its reasoning and rarely questions itself. Use an independent session; never rely on self-review alone.
> - **"Re-run the review on every commit with no memory of earlier results"** → duplicate comments. Supply prior findings and ask for new or unaddressed issues only.
> - **"Put the review criteria in each pipeline script's prompt"** → duplicates configuration; CLAUDE.md keeps it versioned and shared.
> - **"Parse the model's prose with regexes"** → fragile. Use schema-constrained output.
> - **"Switch the blocking check to batches to save 50%"** → no latency guarantee; unacceptable for blocking work (sample question 11, answer A).
> - **"Raise the confidence threshold to cut false positives"** → a number is not a criterion. Specify categories to report and skip.

## Check yourself

<details>
<summary>A pipeline step running <code>claude "Analyze this PR"</code> never finishes. What is wrong and how is it fixed?</summary>

Claude Code is waiting for interactive input. Run it non-interactively with `-p`.
</details>

<details>
<summary>A bot repeats the same ten comments after every push. What change is needed?</summary>

Pass the prior findings into the prompt and instruct Claude to report only new or still-unaddressed issues.
</details>

<details>
<summary>A team wants the code generator to double-check its own output in the same session to save cost. Why is this weak?</summary>

The session retains its generation reasoning and is biased towards its decisions; an independent session reviews more effectively.
</details>
