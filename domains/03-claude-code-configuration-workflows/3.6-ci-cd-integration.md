# 3.6 Integrate Claude Code into CI/CD pipelines

## Knowledge of

- The `-p` (or `--print`) flag for running Claude Code in non-interactive mode in automated pipelines.
- `--output-format json` and `--json-schema` CLI flags for enforcing structured output in CI contexts.
- CLAUDE.md as the mechanism for providing project context (testing standards, fixture conventions, review criteria) to CI-invoked Claude Code.
- Session context isolation: the same Claude session that generated code is less effective at reviewing its own changes than an independent review instance.

## Skills in

- Running Claude Code in CI with the `-p` flag to prevent interactive input hangs.
- Using `--output-format json` with `--json-schema` to produce machine-parseable structured findings for automated posting as inline PR comments.
- Including prior review findings in context when re-running reviews after new commits, instructing Claude to report only new or still-unaddressed issues to avoid duplicate comments.
- Providing existing test files in context so test generation avoids suggesting duplicate scenarios already covered by the test suite.
- Documenting testing standards, valuable test criteria, and available fixtures in CLAUDE.md to improve test generation quality and reduce low-value test output.

## Code snippets

### Non-interactive run: `-p`

```bash
claude -p "Analyze this pull request for security issues"      # processes the prompt, prints, exits
git diff origin/main...HEAD | claude -p "Review this diff for security issues"
```

Without `-p` the job waits for interactive input and hangs. `CLAUDE_HEADLESS` and `--batch` do not exist.

### Machine-parseable findings

```bash
claude -p "Review the staged changes. Report bugs and security issues only." \
  --output-format json \
  --json-schema '{
    "type": "object",
    "properties": {
      "findings": {
        "type": "array",
        "items": {
          "type": "object",
          "properties": {
            "file": {"type": "string"},
            "line": {"type": "integer"},
            "severity": {"enum": ["critical", "high", "medium", "low"]},
            "issue": {"type": "string"},
            "suggested_fix": {"type": "string"}
          },
          "required": ["file", "line", "severity", "issue"]
        }
      }
    },
    "required": ["findings"]
  }' | jq '.structured_output.findings'
```

The response carries `structured_output`. If the run ends without valid structured output the field is absent, so check for it before posting inline PR comments.

### Reproducible CI runs

```bash
# --bare skips hooks, skills, MCP, auto memory and CLAUDE.md from the host machine
claude --bare -p "Summarize README.md" --allowedTools "Read"     # needs ANTHROPIC_API_KEY
```

Bare mode skips CLAUDE.md, so if you want the project's review criteria and test standards, do not use it, or pass them with `--append-system-prompt-file`. Without `--bare`, `claude -p` loads the project's CLAUDE.md like an interactive session.

### Pre-approve only what the job needs

```bash
claude -p "Run the test suite and fix any failures" --allowedTools "Bash,Read,Edit"
claude -p "..." --permission-mode dontAsk   # deny anything not pre-approved; locked-down CI
```

### Context for CI-invoked Claude lives in CLAUDE.md

```markdown
# Testing standards
- Framework: pytest; fixtures in tests/conftest.py (db_session, fake_clock, api_client)
- A valuable test checks behaviour or an edge case, not a getter
- Skip: trivial property tests, tests duplicating existing coverage

# Review criteria
Report: bugs, security issues. Skip: formatting, naming style, minor local patterns.
```

### Re-review after new commits without duplicate comments

```bash
claude -p "Review this diff. Prior findings are below. Report only NEW issues or ones still unaddressed.

<prior_findings>
$(cat prior_findings.json)
</prior_findings>

$(git diff origin/main...HEAD)" --output-format json --json-schema "$SCHEMA"
```

### Test generation without duplicates

```bash
claude -p "Generate tests for src/refunds.py. Existing tests are in tests/test_refunds.py; \
do not repeat scenarios already covered." --allowedTools "Read,Write"
```

### Independent reviewer, not the generating session

Run the review as a separate `claude -p` invocation (a new session with no memory of the generation), not by continuing the session that wrote the code. The generator retains its reasoning context and is less likely to question its own decisions.

```bash
claude -p "Implement the feature in ISSUE.md"            # session A
claude -p "Review the uncommitted changes" --output-format json   # new session B, no --continue/--resume
```
