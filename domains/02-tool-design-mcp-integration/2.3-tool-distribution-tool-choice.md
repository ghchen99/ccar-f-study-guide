# 2.3 Distribute tools appropriately across agents and configure tool choice

## Knowledge of

- Giving an agent too many tools (e.g., 18 instead of 4-5) degrades tool selection reliability by increasing decision complexity.
- Agents with tools outside their specialization tend to misuse them (e.g., a synthesis agent attempting web searches).
- Scoped tool access: giving agents only the tools needed for their role, with limited cross-role tools for specific high-frequency needs.
- `tool_choice` configuration options: `"auto"`, `"any"`, and forced tool selection (`{"type": "tool", "name": "..."}`).

## Skills in

- Restricting each subagent's tool set to those relevant to its role, preventing cross-specialization misuse.
- Replacing generic tools with constrained alternatives (e.g., replacing `fetch_url` with `load_document` that validates document URLs).
- Providing scoped cross-role tools for high-frequency needs (e.g., a `verify_fact` tool for the synthesis agent) while routing complex cases through the coordinator.
- Using `tool_choice` forced selection to ensure a specific tool is called first (e.g., forcing `extract_metadata` before enrichment tools), then processing subsequent steps in follow-up turns.
- Setting `tool_choice: "any"` to guarantee the model calls a tool rather than returning conversational text.

## Code snippets

### Scoped tools per subagent

```python
from claude_agent_sdk import AgentDefinition

agents = {
    "web-searcher": AgentDefinition(
        description="Searches the web and returns claims with sources.",
        prompt="Search the web for the assigned sub-topic.",
        tools=["WebSearch", "WebFetch"],
    ),
    "synthesizer": AgentDefinition(
        description="Merges supplied findings into a report.",
        prompt="Combine the findings. For a simple fact-check use verify_fact; "
               "for anything deeper, say so and the coordinator will delegate.",
        # No WebSearch/WebFetch: only the narrow, scoped cross-role tool
        tools=["Read", "mcp__research__verify_fact"],
    ),
}
```

### Replace a generic tool with a constrained one

```python
# fetch_url(url) accepts anything; load_document validates first
@tool("load_document", "Load a document from an approved document store URL (https://docs.example.com/...).", {"url": str})
async def load_document(args):
    if not args["url"].startswith("https://docs.example.com/"):
        return {"content": [{"type": "text", "text": "URL is not in the approved document store."}], "is_error": True}
    ...
```

### `tool_choice` on the Messages API

```python
import anthropic

client = anthropic.Anthropic()
MODEL = "claude-opus-5"  # see the model note below

# auto (default): Claude may answer in text instead of calling a tool
client.messages.create(model=MODEL, max_tokens=1024, tools=tools, messages=msgs,
                       tool_choice={"type": "auto"})

# any: must call one of the tools, Claude picks which. No conversational text instead.
client.messages.create(model=MODEL, max_tokens=1024, tools=tools, messages=msgs,
                       tool_choice={"type": "any"})

# tool: must call this exact tool
client.messages.create(model=MODEL, max_tokens=1024, tools=tools, messages=msgs,
                       tool_choice={"type": "tool", "name": "extract_metadata"})
```

### Force `extract_metadata` first, then continue with `auto`

```python
first = client.messages.create(
    model=MODEL, max_tokens=1024, tools=tools, messages=msgs,
    tool_choice={"type": "tool", "name": "extract_metadata"},
)
msgs += [
    {"role": "assistant", "content": first.content},
    {"role": "user", "content": [{"type": "tool_result",
                                  "tool_use_id": first.content[0].id,
                                  "content": run_extract_metadata(first.content[0].input)}]},
]
second = client.messages.create(model=MODEL, max_tokens=1024, tools=tools, messages=msgs,
                                tool_choice={"type": "auto"})  # enrichment tools from here
```

Notes from [Define tools](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools):

- With `any` or `tool` the API prefills the assistant turn, so there is no text before the `tool_use` block. Use `auto` plus an instruction in the user message if you want explanation first.
- Changing `tool_choice` invalidates cached message blocks.
- **Model caveat:** forced tool use is not supported everywhere. With manual extended thinking (`thinking: {type: "enabled"}`), `any` and `tool` error. Newer models listed in the docs (e.g. Claude Opus 5.5, Sonnet 5.5) return a 400 for them; use `auto` with `strict: true` tool definitions or structured outputs there. The exam still tests the `auto` / `any` / forced semantics.
