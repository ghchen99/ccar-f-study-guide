# 2.3 Distribute tools appropriately across agents and configure tool choice

> [!NOTE]
> **At a glance**
>
> - **Tool count:** too many tools (18 vs 4-5) degrades selection by raising decision complexity.
> - **Scoping:** give each agent only its role's tools; out-of-role tools get misused (a synthesis agent web searching). Add narrow cross-role tools for high-frequency needs.
> - **`tool_choice`:** `"auto"`, `"any"`, or forced `{"type": "tool", "name": "..."}`.

## Example

### Scoped tools per subagent

```python
from claude_agent_sdk import AgentDefinition

agents = {
    "web-searcher": AgentDefinition(
        description="Searches the web and returns claims with sources.",
        prompt="Search the web for the assigned sub-topic.",
        tools=["WebSearch", "WebFetch"],  # search tools live only with the role that needs them
    ),
    "synthesizer": AgentDefinition(
        description="Merges supplied findings into a report.",
        prompt="Combine the findings. For a simple fact-check use verify_fact; "
               "for anything deeper, say so and the coordinator will delegate.",
        # No WebSearch/WebFetch: only the narrow, scoped cross-role tool
        tools=["Read", "mcp__research__verify_fact"],
    ),
}
```

### Replace a generic tool with a constrained one

```python
# fetch_url(url) accepts anything; load_document validates first
# The constraint lives in code, not in a prompt asking the agent to behave; it also narrows what the agent can reach
@tool("load_document", "Load a document from an approved document store URL (https://docs.example.com/...).", {"url": str})
async def load_document(args):
    if not args["url"].startswith("https://docs.example.com/"):
        return {"content": [{"type": "text", "text": "URL is not in the approved document store."}], "is_error": True}
    ...
```

### `tool_choice` on the Messages API

```python
import anthropic

client = anthropic.Anthropic()
MODEL = "claude-opus-5"  # see the model note below

# auto (default): Claude may answer in text instead of calling a tool
client.messages.create(model=MODEL, max_tokens=1024, tools=tools, messages=msgs,
                       tool_choice={"type": "auto"})

# any: must call one of the tools, Claude picks which. No conversational text instead.
# Use when the output must be structured and the right tool depends on the input
client.messages.create(model=MODEL, max_tokens=1024, tools=tools, messages=msgs,
                       tool_choice={"type": "any"})

# tool: must call this exact tool
client.messages.create(model=MODEL, max_tokens=1024, tools=tools, messages=msgs,
                       tool_choice={"type": "tool", "name": "extract_metadata"})
```

### Force `extract_metadata` first, then continue with `auto`

```python
first = client.messages.create(
    model=MODEL, max_tokens=1024, tools=tools, messages=msgs,  # guarantees the first step; forcing it every turn would prevent the loop from ever finishing
    tool_choice={"type": "tool", "name": "extract_metadata"},
)
msgs += [
    {"role": "assistant", "content": first.content},
    {"role": "user", "content": [{"type": "tool_result",
                                  "tool_use_id": first.content[0].id,
                                  "content": run_extract_metadata(first.content[0].input)}]},
]
second = client.messages.create(model=MODEL, max_tokens=1024, tools=tools, messages=msgs,
                                tool_choice={"type": "auto"})  # enrichment tools from here
```

With `any` or `tool` the API prefills the assistant turn, so no text precedes the `tool_use` block; use `auto` plus an instruction in the user message if you want explanation first. Changing `tool_choice` also invalidates cached message blocks.

## How it works

> [!IMPORTANT]
> **Every visible tool is a candidate in every decision.** Distribute tools by role (least privilege) and use `tool_choice` to remove discretion exactly where it isn't wanted, rather than relying on instructions to keep the model in its lane.

1. **Scope by role.** A synthesis agent holding web search will use it, blurring gathering and combining. Removing the tool removes the failure mode; fewer, relevant tools also mean fewer near-misses.
2. **Add one narrow cross-role tool.** `verify_fact` covers the common simple checks while the prompt routes anything deeper through the coordinator, cutting round trips without handing over full search.
3. **Constrain in code.** `load_document` enforces the URL restriction and states it in the description, so the agent can neither wander nor be talked into it.
4. **Match `tool_choice` to intent.** `auto` allows a text answer; `any` guarantees some tool call (structured output, tool depends on input); a forced tool guarantees a specific call.
5. **Force one step, then return to `auto`.** Forcing `extract_metadata` first guarantees that step without a state machine; forcing every turn would never let the model finish.
6. **Know the costs.** Forcing prefills the turn and invalidates cache, and isn't available in every configuration (see the tip). The semantics are what the exam tests.

## Trade-offs

| Choice | Strength | Cost |
| --- | --- | --- |
| Broad tool access | Fewer round trips | More misuse and attack surface; scope tightly |
| Cross-role `verify_fact` | Cuts latency for the frequent simple case | Coordinator path still needed for complex cases; full toolset trades safety and clarity for speed |
| Batch verification to the end | Fewer trips | Blocking dependencies for later synthesis steps |
| Speculative caching of context | None reliable | Cannot predict what needs verifying; bloats context |
| Forced `tool_choice` | Guarantees one call | A prompt ("call this first") is only probabilistic; for ordering across many calls use programmatic gates ([1.4](../01-agentic-architecture-orchestration/1.4-workflow-enforcement-handoff.md)) |
| `auto` + strict schemas or structured outputs | Similar guarantee where forcing is unavailable | Different route to the same result |
| Per-role tool lists | Easy to audit | One shared global list is simpler but drifts |

> [!WARNING]
> **Exam traps**
>
> - **"Give the synthesis agent all the web search tools"** → violates separation of concerns and over-provisions. Apply least privilege; add only the narrow capability for the common case.
> - **"Batch all verifications and return them at the end"** → blocking dependencies. Don't trade dependent-step correctness for fewer round trips.
> - **"Have the search agent pre-cache extra context"** → speculative and unreliable. Don't build on predictions of what will be needed.
> - **"Tell the agent in the prompt not to use tools outside its role"** → probabilistic. Restrict the tool set rather than instruct restraint.
> - **"Use `any` to make sure one particular tool runs first"** → `any` lets the model choose which. Forcing a specific tool needs the explicit tool form.
> - **"Keep `tool_choice` forced for the whole conversation"** → prevents a final answer. Force the step that needs a guarantee, then return to `auto`.
>
> Sample question 9 (scenario 3) is the canonical form: 85% simple checks, 15% complex. Answer: a scoped `verify_fact` plus the existing coordinator path for the rest.

## Check yourself

<details>
<summary>A report agent keeps issuing web searches although it should only format findings. What is the structural fix?</summary>

Remove search tools from its tool list rather than adding prompt warnings.
</details>

<details>
<summary>An extraction pipeline must always call <code>classify_document</code> first, then proceed normally. Which <code>tool_choice</code> settings are used?</summary>

Forced <code>classify_document</code> on the first request, then <code>auto</code> for later turns.
</details>

<details>
<summary>When is <code>any</code> better than <code>auto</code>?</summary>

When the response must always be a tool call (for example structured output) and the model should pick the right tool for the input.
</details>

> [!TIP]
> **Model caveat:** with manual extended thinking (`thinking: {type: "enabled"}`), `any` and `tool` error. Newer models listed in the docs (e.g. Claude Opus 5.5, Sonnet 5.5) return a 400 for them; use `auto` with `strict: true` tool definitions or structured outputs there.
