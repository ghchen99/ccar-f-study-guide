# 2.5 Select and apply built-in tools (Read, Write, Edit, Bash, Grep, Glob) effectively

> [!NOTE]
> **At a glance**
>
> - **Grep:** searches file contents (function names, error messages, imports).
> - **Glob:** matches file paths by name or extension pattern.
> - **Read / Write / Edit:** Read and Write handle whole files; Edit makes targeted changes via unique text matching.
> - **Fallback:** when Edit fails on non-unique text, Read then Write.

## Example

### Which tool for which question

| Need | Tool | Example input |
| - | - | - |
| Find code by content (callers, error strings, imports) | `Grep` | `{"pattern": "def process_refund", "output_mode": "content", "-n": True}` |
| Find files by name | `Glob` | `{"pattern": "**/*.test.tsx"}` |
| Read a whole file | `Read` | `{"file_path": "/repo/src/refunds.py"}` |
| Targeted change at a unique spot | `Edit` | `{"file_path": ..., "old_string": ..., "new_string": ...}` |
| Create or fully rewrite a file | `Write` | `{"file_path": ..., "content": ...}` |
| Run commands | `Bash` | `{"command": "pytest -q"}` |

Input shapes are from the [Python SDK reference](https://code.claude.com/docs/en/agent-sdk/python.md). `Grep` also takes `glob`, `type`, `-i`, `-A/-B/-C`, `head_limit` and `output_mode` (`content`, `files_with_matches`, `count`).

### Edit with non-unique text: add context, or fall back to Read + Write

```python
# Fails when old_string appears more than once
# Ambiguity is rejected rather than guessed, so the tool never edits the wrong spot silently
{"file_path": "/repo/a.py", "old_string": "return None", "new_string": "return default"}

# Option 1: include enough surrounding lines to be unique
{"file_path": "/repo/a.py",
 "old_string": "    if not order:\n        return None",
 "new_string": "    if not order:\n        return default"}

# Option 2: replace every occurrence deliberately
# Only correct when every occurrence is meant to change
{"file_path": "/repo/a.py", "old_string": "return None", "new_string": "return default", "replace_all": True}

# Option 3 (the exam's fallback): Read the full file, then Write the modified content
# Reliable because it needs no unique anchor, but rewrites the whole file, so review the diff
```

### Build understanding incrementally

```text
1. Grep  "def process_refund"                      -> find the entry point
2. Read  refunds.py                                -> see what it imports and calls
3. Grep  "from payments import|import payments"    -> follow one dependency
4. Read  only the files the trace points to
```

Do not Read every file up front.

### Trace usage through wrapper modules

```text
1. Read  utils/http.py; list the exported names: fetch_json, post_json, retry
2. Grep each name separately across the repo: "fetch_json", "post_json", "retry"
   (a caller may import the wrapper under a different name or re-export it)
```

### Restrict which built-ins an agent can use

```python
from claude_agent_sdk import ClaudeAgentOptions

# Availability: only these built-ins exist for Claude. Permission: these are auto-approved.
# A read-only toolset makes mutation impossible, which is stronger than asking the agent not to edit
ClaudeAgentOptions(tools=["Read", "Grep", "Glob"], allowed_tools=["Read", "Grep", "Glob"])
```

## How it works

> [!IMPORTANT]
> **Match the question to the instrument.** Explore incrementally, starting narrow and following evidence rather than loading everything up front, and know the fallback when a precise tool can't be applied.

1. **Map question to tool.** "Who calls this" is content (Grep); "which files are tests" is name (Glob). Swapping them returns noise or nothing.
2. **Search, then read.** Grep returns matches, not whole files, so it locates entry points cheaply; Read then loads only what the matches point to.
3. **Resolve Edit ambiguity.** A repeated `old_string` fails rather than guesses. Add surrounding lines, use `replace_all` only if every occurrence should change, or Read then Write.
4. **Treat Read + Write as a fallback.** It needs no anchor but regenerates the whole file, so check the diff for unrelated changes.
5. **Trace through wrappers.** A caller may import a function under another name or re-export it. List the module's exports, then search each name.
6. **Restrict availability.** Read-only `tools` makes mutation impossible. Availability (what exists) differs from permission (what is auto-approved).

## Trade-offs

| Choice | Strength | Cost |
| --- | --- | --- |
| Dedicated tools vs Bash `grep`/`find` | Structured, bounded output; the intended mechanism | Shell works but is less controlled and harder to permission |
| Edit | Minimal change; preserves the rest of the file | Needs a unique anchor |
| Read + Write | Robust to non-unique anchors | Heavier and riskier for large files |
| Incremental exploration | Cheaper, focused reasoning | Can miss distant dependencies; targeted follow-up searches mitigate |
| Search first vs broad Read | Search narrows what to read | Full read is justified once the file is known relevant |
| Subagent exploration | Keeps main context clean ([5.4](../05-context-management-reliability/5.4-codebase-exploration-context.md)) | Inline is simpler for small questions |
| Restrictive toolset | Deterministic | Instructions are not |

> [!WARNING]
> **Exam traps**
>
> - **"Use Grep to find all `*.test.tsx` files"** → Grep searches contents, not names. File-name patterns are Glob's job.
> - **"Use Glob to find every caller of `process_refund`"** → Glob matches paths only. Content questions need Grep.
> - **"Read all source files first to build a complete picture"** → floods context. Build understanding incrementally from Grep entry points.
> - **"Edit failed because the text is not unique, so retry the same Edit"** → it fails again. Add context, use `replace_all` deliberately, or fall back to Read + Write.
> - **"Search once for the function name to find all usages"** → misses aliases and re-exports. Enumerate wrapper exports and search each.
> - **"Use Write for a one-line change"** → rewrites the whole file and risks unrelated changes. Use Edit at a unique spot.
> - **"Ask the agent not to modify files"** → probabilistic. Limit the tool set.

## Check yourself

<details>
<summary>You need every file named <code>*.config.ts</code> under the repo. Which tool?</summary>

Glob, since it matches file path patterns, not contents.
</details>

<details>
<summary>An Edit fails because <code>return None</code> appears eleven times, and only one should change. What are the options?</summary>

Expand <code>old_string</code> with unique surrounding lines; failing that, Read the file and Write the modified version.
</details>

<details>
<summary>A utility module re-exports <code>fetch_json</code> as <code>get</code>. How is every caller found?</summary>

Read the module to list its exports and aliases, then Grep each name separately.
</details>
