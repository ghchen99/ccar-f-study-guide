# 5.3 Implement error propagation strategies across multi-agent systems

## Knowledge of

- Structured error context (failure type, attempted query, partial results, alternative approaches) as enabling intelligent coordinator recovery decisions.
- The distinction between access failures (timeouts needing retry decisions) and valid empty results (successful queries with no matches).
- Why generic error statuses ("search unavailable") hide valuable context from the coordinator.
- Why silently suppressing errors (returning empty results as success) or terminating entire workflows on single failures are both anti-patterns.

## Skills in

- Returning structured error context including failure type, what was attempted, partial results, and potential alternatives to enable coordinator recovery.
- Distinguishing access failures from valid empty results in error reporting so the coordinator can make appropriate decisions.
- Having subagents implement local recovery for transient failures and only propagate errors they cannot resolve, including what was attempted and partial results.
- Structuring synthesis output with coverage annotations indicating which findings are well-supported versus which topic areas have gaps due to unavailable sources.

## Code snippets

### Structured error context from a subagent

```python
from typing import Literal, TypedDict


class SubagentError(TypedDict):
    status: Literal["error"]
    failure_type: Literal["timeout", "rate_limit", "auth", "source_unavailable"]
    attempted_query: str
    attempts: int                  # retries already done locally
    partial_results: list[dict]    # whatever was gathered before failing
    alternatives: list[str]        # what the coordinator could try next
```

def web_search_agent(query: str) -> dict:
    results: list[dict] = []
    for attempt in range(1, 4):
        try:
            results = search(query)                    # transient failures retried locally
            return {"status": "ok", "results": results}
        except TimeoutError:
            continue
    return {
        "status": "error", "failure_type": "timeout", "attempted_query": query,
        "attempts": 3, "partial_results": results,
        "alternatives": ["retry with a narrower query", "use the document-analysis agent"],

### Access failure vs valid empty result

```python
{"status": "ok", "results": []}          # searched fine, nothing matches: coverage statement, not an error
{"status": "error", "failure_type": "timeout", ...}   # could not search: coordinator must decide
```

### Anti-patterns

```python
return {"status": "ok", "results": []}       # swallowed timeout: looks like "no results", hides the gap
return {"status": "error", "message": "search unavailable"}   # generic: nothing to recover with
raise                                         # kills the whole research run for one subagent failure
```

### Coordinator recovery and coverage annotations

```python
def synthesize(topic_results: dict[str, dict]) -> str:
    well_supported = [t for t, r in topic_results.items() if r["status"] == "ok" and r["results"]]
    gaps = {t: r for t, r in topic_results.items() if r["status"] == "error"}
    report = ["## Findings", *render_findings(well_supported)]
    if gaps:
        report.append("## Coverage gaps")
        for topic, err in gaps.items():
            report.append(f"- {topic}: not covered ({err['failure_type']} on '{err['attempted_query']}'). "
                          f"Partial: {len(err['partial_results'])} items.")
    return "\n".join(report)
```

The report states which areas are well supported and which have gaps from unavailable sources.
