# 5.3 Implement error propagation strategies across multi-agent systems

> [!NOTE]
> **At a glance**
>
> - **Structured errors:** failure type, attempted query, partial results and alternatives let the coordinator recover intelligently.
> - **Failure vs empty:** a timeout is an access failure; zero matches is a valid result.
> - **Generic statuses:** "search unavailable" hides the context recovery needs.
> - **Anti-patterns:** silently returning empty success, or aborting the whole workflow on one failure.

## Example

### Structured error context from a subagent

```python
from typing import Literal, TypedDict


class SubagentError(TypedDict):
    status: Literal["error"]   # distinct from "ok" so an access failure is never read as "no results"
    failure_type: Literal["timeout", "rate_limit", "auth", "source_unavailable"]  # drives the coordinator's choice: retry, reroute or accept the gap
    attempted_query: str
    attempts: int                  # retries already done locally
    partial_results: list[dict]    # whatever was gathered before failing
    alternatives: list[str]        # what the coordinator could try next
```

```python
def web_search_agent(query: str) -> dict:
    # Local retry absorbs transient faults; only what the subagent cannot fix reaches the coordinator.
    results: list[dict] = []
    for attempt in range(1, 4):
        try:
            results = search(query)                    # transient failures retried locally
            return {"status": "ok", "results": results}
        except TimeoutError:
            continue
    return {
        "status": "error", "failure_type": "timeout", "attempted_query": query,
        "attempts": 3, "partial_results": results,
        "alternatives": ["retry with a narrower query", "use the document-analysis agent"],
    }
```

### Access failure vs valid empty result

```python
{"status": "ok", "results": []}          # searched fine, nothing matches: coverage statement, not an error
{"status": "error", "failure_type": "timeout", ...}   # could not search: coordinator must decide
```

### Anti-patterns

```python
return {"status": "ok", "results": []}       # swallowed timeout: looks like "no results", hides the gap
return {"status": "error", "message": "search unavailable"}   # generic: nothing to recover with
raise                                         # kills the whole research run for one subagent failure
```

### Coordinator recovery and coverage annotations

```python
def synthesize(topic_results: dict[str, dict]) -> str:
    # One failed topic degrades the report with a stated gap; it does not abort the run.
    well_supported = [t for t, r in topic_results.items() if r["status"] == "ok" and r["results"]]
    gaps = {t: r for t, r in topic_results.items() if r["status"] == "error"}
    report = ["## Findings", *render_findings(well_supported)]
    if gaps:
        report.append("## Coverage gaps")
        for topic, err in gaps.items():
            # Readers see what is missing and why, so absence is not mistaken for "nothing exists".
            report.append(f"- {topic}: not covered ({err['failure_type']} on '{err['attempted_query']}'). "
                          f"Partial: {len(err['partial_results'])} items.")
    return "\n".join(report)
```

The report states which areas are well supported and which have gaps from unavailable sources.

## How it works

> [!IMPORTANT]
> **A failure is information for whoever can act on it.** The subagent absorbs transient faults locally and reports only what it cannot fix, with enough structure for the coordinator to retry, reroute or proceed with a declared gap. Never hide it, never abort over it.

1. **Carry actionable fields.** `failure_type` separates a retryable timeout from an auth failure; `attempted_query`, `partial_results` and `alternatives` show what was tried, what survives and what to try next.
2. **Retry at the lowest level.** The local loop retries transient faults up to three times, keeping coordinator context clear; `attempts` stops the coordinator repeating it.
3. **Keep shapes distinct.** An empty `ok` is a coverage statement ("searched, nothing matches"); an `error` is "could not search". Merging them makes a broken source look like a topic with no literature.
4. **Avoid the three anti-patterns.** A swallowed timeout leaves a silent gap, a generic status gives no basis for recovery, and an unhandled raise kills the whole run.
5. **Annotate gaps.** `synthesize` renders failure type and query, so the reader learns music was not covered because of a timeout, not that it has no findings.
6. **Keep partial results.** They are counted in the gap line so usable material is not discarded.

## Trade-offs

| Choice | Strength | Cost |
| --- | --- | --- |
| Local retry | Cuts coordinator traffic for transient faults | Delays reporting and can hide a flaky source; `attempts` keeps it visible. Propagate non-retryable errors (auth, validation) at once |
| Structured error | Enables intelligent recovery | Needs a schema and discipline in every subagent |
| Generic status | Easy | Leaves the coordinator guessing |
| Proceed with partial results | Stated gap beats no report | If a missing source invalidates the conclusion, the coordinator should stop or escalate |
| Coordinator retry | Recovers more failures | Unbounded retry risks cost and loops; cap attempts and track alternatives tried |
| Coverage annotations | Honest | Less tidy; for completeness-dependent decisions, honesty wins |

> [!WARNING]
> **Exam traps**
>
> - **"Catch the timeout and return an empty result marked successful"** → suppresses the error and prevents recovery. Never mark a failure as an empty success.
> - **"Propagate to a top-level handler that terminates the workflow"** → one failure should not end the run. Contain and report; the coordinator decides.
> - **"Retry, then return a generic 'search unavailable'"** → hides failure type, query and partial results. Structured error context is the correct answer.
> - **"Treat empty results as errors so the coordinator retries"** → a valid empty result is information. Separate access failures from empty results.
> - **"Hide gaps to keep the report clean"** → readers assume coverage that does not exist. Annotate gaps and their cause.

## Check yourself

<details>
<summary>A subagent's source times out three times. What should the coordinator receive?</summary>

A structured error with failure type, attempted query, attempts made, any partial results and suggested alternatives, so it can retry differently, reroute or note the gap.
</details>

<details>
<summary>A search succeeds and returns zero matches. Is this an error?</summary>

No. It is a valid empty result and a coverage statement, reported as a success so it is not confused with an access failure.
</details>

<details>
<summary>Two of five topics could not be searched. Should the report be withheld?</summary>

Usually no. Produce the report with the three supported topics and an explicit coverage-gaps section, unless the missing topics make the conclusion unreliable.
</details>
