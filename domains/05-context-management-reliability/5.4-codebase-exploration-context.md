# 5.4 Manage context effectively in large codebase exploration

## Knowledge of

- Context degradation in extended sessions: models start giving inconsistent answers and referencing "typical patterns" rather than specific classes discovered earlier.
- The role of scratchpad files for persisting key findings across context boundaries.
- Subagent delegation for isolating verbose exploration output while the main agent coordinates high-level understanding.
- Structured state persistence for crash recovery: each agent exports state to a known location, and the coordinator loads a manifest on resume.

## Skills in

- Spawning subagents to investigate specific questions (e.g., "find all test files," "trace refund flow dependencies") while the main agent preserves high-level coordination.
- Having agents maintain scratchpad files recording key findings, referencing them for subsequent questions to counteract context degradation.
- Summarizing key findings from one exploration phase before spawning sub-agents for the next phase, injecting summaries into initial context.
- Designing crash recovery using structured agent state exports (manifests) that the coordinator loads on resume and injects into agent prompts.
- Using `/compact` to reduce context usage during extended exploration sessions when context fills with verbose discovery output.

## Code snippets

### Scratchpad file for findings that must survive context loss

```text
Instruction in the prompt or CLAUDE.md:
"Maintain SCRATCHPAD.md. After each exploration step append: files examined, key classes
 (with paths), data flow, open questions. Re-read it before answering follow-up questions
 instead of relying on memory."
```

```markdown
<!-- SCRATCHPAD.md -->
## Refund flow
- Entry: payments/refunds.py:process_refund() -> RefundPolicyChecker (policy/checker.py)
- Writes: ledger/entries.py:LedgerEntry; emits RefundIssued event (events/bus.py)
## Open questions
- Where is the partial-refund rounding done?
```

Late in a long session, a degrading model starts saying "typical patterns" instead of naming the specific classes it found. The scratchpad counters that.

### Delegate verbose exploration, keep a summary

```text
Use the Explore subagent: "Find all test files related to refunds and list how each is run."
Use a subagent: "Trace the refund flow and return the call chain with file:line references only."
```

The subagent's tool calls stay in its own context; only its final message returns.

### Summarise one phase before starting the next

```python
# The summary, not the raw exploration trail, seeds the next phase: it carries conclusions without the bulk.
phase1_summary = ask("Summarise findings from the exploration so far: modules, entry points, risks.")
phase2 = ask(f"<prior_findings>\n{phase1_summary}\n</prior_findings>\n\nNow investigate the ledger writes.")
```

### Control compaction

```text
/compact                       compact on demand when verbose discovery output has filled context
```

```markdown
<!-- CLAUDE.md: tells the compactor what to preserve -->
# Summary instructions
When summarising this conversation, always preserve:
- The current task objective and acceptance criteria
- File paths that have been read or modified
- Test results and error messages
- Decisions made and the reasoning behind them
```

Project-root CLAUDE.md is re-read after compaction, so persistent rules belong there rather than in the first prompt. In the Agent SDK a `PreCompact` hook (input has `trigger: "manual" | "auto"`) can archive the full transcript before it is summarised.

### Crash recovery with a manifest

Each agent writes its state to a known location; the coordinator loads the manifest on resume and injects it into agent prompts.

```python
import json
from pathlib import Path

STATE_DIR = Path(".agent_state")


def save_state(agent: str, state: dict) -> None:
    # State is written as work progresses, not at exit, so a crash still leaves a usable checkpoint.
    STATE_DIR.mkdir(exist_ok=True)
    (STATE_DIR / f"{agent}.json").write_text(json.dumps(state, indent=2))
    manifest = {p.stem: {"updated": p.stat().st_mtime, "path": str(p)} for p in STATE_DIR.glob("*.json") if p.stem != "manifest"}
    (STATE_DIR / "manifest.json").write_text(json.dumps(manifest, indent=2))


def # The manifest is the single entry point; the coordinator needs no knowledge of each agent's file layout.
    resume_prompts() -> dict[str, str]:
    manifest = json.loads((STATE_DIR / "manifest.json").read_text())
    return {
        agent: f"<prior_state>\n{Path(meta['path']).read_text()}\n</prior_state>\nContinue from this state."
        for agent, meta in manifest.items()
    }
```

## Commentary: the concepts behind the code

SDK names are illustrative; know the concept, not the exact parameter.

### The design decision

Long exploration produces far more output than understanding. The design keeps the main context for high-level coordination and conclusions, pushes verbose discovery into isolated subagent contexts that return only summaries, and writes durable findings to files (a scratchpad, saved state, a manifest) that outlive both context compaction and crashes. The principle: what must persist is stored outside the context window and reloaded deliberately; what is merely noisy is isolated so it never enters the main context.

### Walk-through

- Context degradation in a long session shows up as vague answers: "typical patterns" in place of the specific classes found earlier. The scratchpad holds files examined, key classes with paths, data flow and open questions, and the agent re-reads it before follow-ups instead of trusting its memory. Specific paths in the file are what restore specific answers.
- Subagent delegation ("find all test files", "trace the refund flow, return file:line references only") keeps the dozens of Grep and Read calls in the subagent's context. Only its final message returns, so the main agent keeps a clean picture. Asking for references only (not file contents) is what makes the summary small.
- Summarising phase 1 before phase 2 injects conclusions, not the raw trail, into the next stage's initial context. This is also how information crosses between agents that do not share memory.
- `/compact` reduces context when discovery output has filled it. The CLAUDE.md "summary instructions" tell compaction what must survive (objective, touched files, test results, decisions and reasoning). Persistent rules belong in project-root CLAUDE.md because it is re-read after compaction, whereas a first-prompt instruction can be summarised away.
- A pre-compaction hook that archives the transcript preserves the full record before summarisation. Compaction is lossy by design; archiving keeps an escape hatch.
- `save_state` and the manifest address crashes. Each agent writes state to a known location; on resume, the coordinator reads the manifest and injects each agent's saved state into its prompt. Without this, a crash means re-exploring from scratch, and the model cannot recall anything it learned.
- The manifest is an index rather than a copy of state, so the coordinator can see what exists and when it was updated without knowing each agent's layout.

### Trade-offs and alternatives

- **Subagent vs doing it inline:** a subagent protects the main context but adds startup cost, loses the nuance not included in its summary and cannot see the conversation unless given context. Inline is cheaper for a single small lookup.
- **Scratchpad vs `/compact` alone:** compaction is automatic but lossy and unpredictable about detail; a scratchpad is explicit and exact but needs the agent to maintain it. They complement each other.
- **Resume vs fresh start with a summary:** resuming keeps full history but includes stale tool results if files have changed; a fresh session seeded with a distilled summary is more reliable when much has changed (see 1.7).
- **Manifest granularity:** frequent state saves reduce lost work and add write overhead; too little detail in state makes resumed agents re-derive things.
- **Narrow vs broad exploration:** reading everything up front is thorough and floods context; incremental Grep-then-Read stays focused but may miss unexpected connections.
- **Persistent files vs memory in the model:** files are inspectable and survive crashes; model memory is neither.

### Exam traps

- "Read the whole repository first so the agent has everything": exhausts context and accelerates degradation. Rule: explore incrementally and delegate verbose discovery.
- "Rely on a larger context window": bigger windows still degrade over long sessions and do not survive a crash. Rule: persist key findings externally.
- "Keep all findings in the conversation; the model will remember": earlier discoveries get paraphrased into "typical patterns". Rule: use a scratchpad and re-read it.
- "Have the subagent return everything it read": defeats the isolation. Rule: ask for a summary with specific references.
- "Restart from scratch after a crash": loses all progress. Rule: persist structured agent state and load a manifest on resume.
- "Put persistent rules only in the first prompt": they may be compacted away. Rule: put them in project CLAUDE.md, re-read after compaction.

### Check yourself

- Two hours into a codebase investigation the agent answers with generic patterns instead of the classes it found earlier. What mitigates this? A scratchpad of key findings with paths that is re-read before answering, plus delegating verbose exploration to subagents and compacting when needed.
- The main agent's context is full of Grep and Read output from tracing a flow. How should the next trace be done? Delegate it to a subagent that returns a short call chain with file and line references only.
- A multi-agent exploration crashes halfway. How is progress recovered? Each agent has exported state to a known location; the coordinator loads the manifest and injects each agent's saved state into its prompt on resume.
