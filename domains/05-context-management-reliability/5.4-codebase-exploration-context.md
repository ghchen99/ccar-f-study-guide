# 5.4 Manage context effectively in large codebase exploration

> [!NOTE]
> **At a glance**
>
> - **Degradation:** long sessions drift into "typical patterns" instead of the specific classes found earlier.
> - **Scratchpad:** key findings in a file survive context boundaries and are re-read before answering.
> - **Delegation:** subagents isolate verbose exploration; the main agent keeps high-level understanding.
> - **Crash recovery:** agents export state to a known location; the coordinator loads a manifest on resume.

## Example

### Scratchpad file for findings that must survive context loss

```text
Instruction in the prompt or CLAUDE.md:
"Maintain SCRATCHPAD.md. After each exploration step append: files examined, key classes
 (with paths), data flow, open questions. Re-read it before answering follow-up questions
 instead of relying on memory."
```

```markdown
<!-- SCRATCHPAD.md -->
## Refund flow
- Entry: payments/refunds.py:process_refund() -> RefundPolicyChecker (policy/checker.py)
- Writes: ledger/entries.py:LedgerEntry; emits RefundIssued event (events/bus.py)
## Open questions
- Where is the partial-refund rounding done?
```

Late in a long session a degrading model says "typical patterns" instead of naming specific classes; the scratchpad counters that.

### Delegate verbose exploration, keep a summary

```text
Use the Explore subagent: "Find all test files related to refunds and list how each is run."
Use a subagent: "Trace the refund flow and return the call chain with file:line references only."
```

The subagent's tool calls stay in its own context; only its final message returns.

### Summarise one phase before starting the next

```python
# The summary, not the raw exploration trail, seeds the next phase: it carries conclusions without the bulk.
phase1_summary = ask("Summarise findings from the exploration so far: modules, entry points, risks.")
phase2 = ask(f"<prior_findings>\n{phase1_summary}\n</prior_findings>\n\nNow investigate the ledger writes.")
```

### Control compaction

```text
/compact                       compact on demand when verbose discovery output has filled context
```

```markdown
<!-- CLAUDE.md: tells the compactor what to preserve -->
# Summary instructions
When summarising this conversation, always preserve:
- The current task objective and acceptance criteria
- File paths that have been read or modified
- Test results and error messages
- Decisions made and the reasoning behind them
```

Project-root CLAUDE.md is re-read after compaction, so persistent rules belong there rather than in the first prompt. In the Agent SDK a `PreCompact` hook (input has `trigger: "manual" | "auto"`) can archive the full transcript before it is summarised.

### Crash recovery with a manifest

Each agent writes its state to a known location; the coordinator loads the manifest on resume and injects it into agent prompts.

```python
import json
from pathlib import Path

STATE_DIR = Path(".agent_state")


def save_state(agent: str, state: dict) -> None:
    # State is written as work progresses, not at exit, so a crash still leaves a usable checkpoint.
    STATE_DIR.mkdir(exist_ok=True)
    (STATE_DIR / f"{agent}.json").write_text(json.dumps(state, indent=2))
    manifest = {p.stem: {"updated": p.stat().st_mtime, "path": str(p)} for p in STATE_DIR.glob("*.json") if p.stem != "manifest"}
    (STATE_DIR / "manifest.json").write_text(json.dumps(manifest, indent=2))


def resume_prompts() -> dict[str, str]:
    # The manifest is the single entry point; the coordinator needs no knowledge of each agent's file layout.
    manifest = json.loads((STATE_DIR / "manifest.json").read_text())
    return {
        agent: f"<prior_state>\n{Path(meta['path']).read_text()}\n</prior_state>\nContinue from this state."
        for agent, meta in manifest.items()
    }
```

## How it works

> [!IMPORTANT]
> **Persist what matters outside the window; isolate what is merely noisy.** The main context holds coordination and conclusions; verbose discovery runs in subagent contexts that return summaries, and durable findings go to files that outlive compaction and crashes.

1. **Scratchpad.** Files examined, key classes with paths, data flow and open questions, re-read before follow-ups. Specific paths restore specific answers.
2. **Delegate discovery.** The subagent absorbs dozens of Grep and Read calls and returns only a final message; asking for references, not contents, keeps it small.
3. **Summarise per phase.** Conclusions, not the raw trail, seed the next phase; this is also how information crosses between agents that share no memory.
4. **Control compaction.** `/compact` frees space; CLAUDE.md summary instructions say what must survive. Project-root CLAUDE.md is re-read afterwards, but a first-prompt rule can be summarised away. A pre-compaction hook can archive the full transcript.
5. **Save state and a manifest.** On resume the coordinator reads the manifest and injects each agent's state; otherwise a crash means re-exploring from scratch.
6. **Index, don't copy.** The manifest shows what exists and when it changed without exposing each agent's layout.

## Trade-offs

| Choice | Strength | Cost |
| --- | --- | --- |
| Subagent | Protects main context | Startup cost; loses nuance outside its summary; needs context passed in. Inline is cheaper for one small lookup |
| Scratchpad | Explicit and exact | Agent must maintain it; complements automatic but lossy `/compact` |
| Resume | Keeps full history | Stale tool results if files changed |
| Fresh session with summary | More reliable after many changes ([1.7](../01-agentic-architecture-orchestration/1.7-session-state-resumption-forking.md)) | Depends on summary quality |
| Frequent state saves | Less lost work | Write overhead; too little state forces re-derivation |
| Read everything first | Thorough | Floods context |
| Incremental Grep then Read | Focused | May miss unexpected connections |

Files are inspectable and survive crashes; model memory is neither.

> [!WARNING]
> **Exam traps**
>
> - **"Read the whole repository first"** → exhausts context and accelerates degradation. Explore incrementally and delegate verbose discovery.
> - **"Rely on a larger context window"** → still degrades and does not survive a crash. Persist key findings externally.
> - **"Keep findings in the conversation; the model will remember"** → discoveries get paraphrased into "typical patterns". Use a scratchpad and re-read it.
> - **"Have the subagent return everything it read"** → defeats isolation. Ask for a summary with specific references.
> - **"Restart from scratch after a crash"** → loses all progress. Persist structured state and load a manifest on resume.
> - **"Put persistent rules only in the first prompt"** → may be compacted away. Use project CLAUDE.md.

## Check yourself

<details>
<summary>Two hours into an investigation the agent answers with generic patterns instead of the classes it found earlier. What mitigates this?</summary>

A scratchpad of key findings with paths, re-read before answering, plus delegating verbose exploration to subagents and compacting when needed.
</details>

<details>
<summary>The main agent's context is full of Grep and Read output from tracing a flow. How should the next trace be done?</summary>

Delegate it to a subagent that returns a short call chain with file and line references only.
</details>

<details>
<summary>A multi-agent exploration crashes halfway. How is progress recovered?</summary>

Each agent has exported state to a known location; on resume the coordinator loads the manifest and injects each agent's saved state into its prompt.
</details>
