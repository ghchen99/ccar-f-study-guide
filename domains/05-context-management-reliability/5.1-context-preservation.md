# 5.1 Manage conversation context to preserve critical information across long interactions

## Knowledge of

- Progressive summarization risks: condensing numerical values, percentages, dates, and customer-stated expectations into vague summaries.
- The "lost in the middle" effect: models reliably process information at the beginning and end of long inputs but may omit findings from middle sections.
- How tool results accumulate in context and consume tokens disproportionately to their relevance (e.g., 40+ fields per order lookup when only 5 are relevant).
- The importance of passing complete conversation history in subsequent API requests to maintain conversational coherence.

## Skills in

- Extracting transactional facts (amounts, dates, order numbers, statuses) into a persistent "case facts" block included in each prompt, outside summarized history.
- Extracting and persisting structured issue data (order IDs, amounts, statuses) into a separate context layer for multi-issue sessions.
- Trimming verbose tool outputs to only relevant fields before they accumulate in context (e.g., keeping only return-relevant fields from order lookups).
- Placing key findings summaries at the beginning of aggregated inputs and organizing detailed results with explicit section headers to mitigate position effects.
- Requiring subagents to include metadata (dates, source locations, methodological context) in structured outputs to support accurate downstream synthesis.
- Modifying upstream agents to return structured data (key facts, citations, relevance scores) instead of verbose content and reasoning chains when downstream agents have limited context budgets.

## Code snippets

### Persistent "case facts" block outside summarised history

Amounts, dates, order numbers and statuses live in a structured block rebuilt into every request, so summarisation cannot blur "$84.50 refund, requested 2026-03-02" into "a refund".

```python
from dataclasses import dataclass, field


@dataclass
class CaseFacts:
    customer_id: str | None = None
    issues: list[dict] = field(default_factory=list)   # one entry per concern in a multi-issue session

    def render(self) -> str:
        lines = [f"customer_id: {self.customer_id}"]
        for i in self.issues:
            lines.append(f"- {i['type']} | order {i['order_id']} | ${i['amount']:.2f} | "
                         f"status {i['status']} | opened {i['opened']}")
        return "<case_facts>\n" + "\n".join(lines) + "\n</case_facts>"


def build_request(facts: CaseFacts, summarised_history: list[dict], new_user_msg: str) -> dict:
    return {
        "system": SYSTEM_PROMPT + "\n\n" + facts.render(),    # facts first, never summarised
        "messages": summarised_history + [{"role": "user", "content": new_user_msg}],
    }
```

### Trim verbose tool output to the fields that matter

A 40-field order lookup becomes the five fields relevant to returns before it is appended to history.

```python
RETURN_FIELDS = ("order_id", "status", "items", "total", "delivered_at")


def trim_order(raw: dict) -> dict:
    return {k: raw[k] for k in RETURN_FIELDS if k in raw}


# in the agent loop, before returning the tool_result:
content = json.dumps(trim_order(execute_tool(name, args)))
```

With the Agent SDK the same trimming can be done in a `PostToolUse` hook via `updatedToolOutput` (see [1.5](../01-agentic-architecture-orchestration/1.5-hooks-interception-normalization.md)).

### Mitigate "lost in the middle" when aggregating

Put the key findings summary first, then detail under explicit headers.

```python
def aggregate(findings: list[dict], summary: str) -> str:
    sections = "\n\n".join(f"## {f['topic']}\n{f['detail']}\nSource: {f['source']} ({f['date']})" for f in findings)
    return f"## Key findings (read first)\n{summary}\n\n{sections}"
```

### Upstream agents return structured data, not transcripts

```json
{
  "claim": "Streaming revenue grew 14% in 2025",
  "evidence_excerpt": "revenue from streaming rose 14%",
  "source_url": "https://example.com/report",
  "published": "2026-01-10",
  "relevance": 0.9
}
```

When a downstream agent has a limited context budget, return key facts, citations and relevance scores rather than verbose content and reasoning chains.

### Keep the full history in each request

The Messages API is stateless: send the full conversation (including tool calls and results) on every call to keep it coherent.
