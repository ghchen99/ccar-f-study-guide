# 5.5 Design human review workflows and confidence calibration

## Knowledge of

- The risk that aggregate accuracy metrics (e.g., 97% overall) may mask poor performance on specific document types or fields.
- Stratified random sampling for measuring error rates in high-confidence extractions and detecting novel error patterns.
- Field-level confidence scores calibrated using labeled validation sets for routing review attention.
- The importance of validating accuracy by document type and field segment before automating high-confidence extractions.

## Skills in

- Implementing stratified random sampling of high-confidence extractions for ongoing error rate measurement and novel pattern detection.
- Analyzing accuracy by document type and field to verify consistent performance across all segments before reducing human review.
- Having models output field-level confidence scores, then calibrating review thresholds using labeled validation sets.
- Routing extractions with low model confidence or ambiguous/contradictory source documents to human review, prioritizing limited reviewer capacity.

## Code snippets

### Aggregate accuracy hides segment failures

```python
import pandas as pd

df = pd.read_csv("labelled_validation.csv")     # columns: doc_type, field, correct (bool), confidence

print("overall", df.correct.mean())                                   # 0.97 looks fine
print(df.groupby("doc_type").correct.mean())                          # but handwritten_receipts: 0.71
# Count matters: a 100% mean on a handful of rows is not evidence.
print(df.groupby(["doc_type", "field"]).correct.agg(["mean", "count"]).sort_values("mean").head(10))
```

Validate accuracy by document type and by field before automating anything.

### Calibrate thresholds on a labelled validation set

```python
def precision_at(df, field: str, threshold: float) -> float:
    # Measured against human labels: this is what turns a raw confidence number into a real accuracy estimate.
    kept = df[(df.field == field) & (df.confidence >= threshold)]
    return kept.correct.mean()


# smallest threshold where auto-accepted fields meet the accuracy target
def pick_threshold(df, field: str, target: float = 0.98) -> float:
    for t in [i / 100 for i in range(50, 100)]:
        if precision_at(df, field, t) >= target:
            return t
    return 1.01     # never auto-accept this field
```

Calibrate per field; model self-reported confidence is only meaningful once checked against labels.

### Route to human review

```python
def route(extraction: dict, thresholds: dict[str, float], source_flags: dict) -> str:
    # Source problems override confidence: a model can be confident about a value the document itself contradicts.
    if source_flags.get("contradictory") or source_flags.get("ambiguous"):
        return "human_review"
    for field, item in extraction.items():
        if item["confidence"] < thresholds[field]:
            return "human_review"
    return "auto_accept"
```

### Stratified random sampling of high-confidence output

Keep measuring after automation: sample auto-accepted extractions per document type and field, and review them.

```python
import random

def # Stratify by type and field so rare segments are sampled, which a single uniform sample would underrepresent.
    sample_for_audit(auto_accepted: list[dict], per_stratum: int = 20) -> list[dict]:
    strata: dict[tuple, list[dict]] = {}
    for rec in auto_accepted:
        strata.setdefault((rec["doc_type"], rec["field"]), []).append(rec)
    return [r for recs in strata.values() for r in random.sample(recs, min(per_stratum, len(recs)))]
```

This estimates the error rate of high-confidence output and surfaces new error patterns, and lets you prioritise limited reviewer time on the low-confidence and contradictory cases.

## Commentary: the concepts behind the code

SDK names are illustrative; know the concept, not the exact parameter.

### The design decision

Automation of extraction is earned segment by segment, with measurement rather than trust. Confidence scores are treated as hypotheses to be calibrated against labelled data, accuracy is judged per document type and per field instead of in aggregate, and review effort is directed where it adds most value: low-confidence, ambiguous or contradictory items. After automation begins, stratified random sampling of the high-confidence output keeps measuring, so drift and novel error patterns are detected instead of assumed away.

### Walk-through

- The first snippet shows the aggregate trap. 97% overall is compatible with 71% on handwritten receipts if that type is a small share of volume. The group-by on document type, then on type and field, exposes the weak segment. The `count` column guards against reading a perfect mean on a handful of rows as proof.
- Field-level confidence in the schema (a `value` and `confidence` per field) lets review attention be spent on the uncertain field, such as `total` at 0.62, rather than rereading a whole document whose vendor field is fine. A null `due_date` with confidence 0.0 is a legitimate "not present" signal, not a guess.
- `precision_at` and `pick_threshold` calibrate: for each field, find the lowest confidence cut-off at which auto-accepted values meet the accuracy target on labelled data. Different fields get different thresholds because they have different difficulty. The return of 1.01 means "never auto-accept this field" when no threshold reaches the target.
- Raw model confidence is not assumed to equal probability of being correct. The labelled set is what ties the number to reality.
- `route` sends anything with a contradictory or ambiguous source to human review regardless of confidence. A model can be confident about a value that the document itself contradicts; confidence measures the model's certainty, not the source's consistency.
- `sample_for_audit` samples per stratum (document type and field). A single uniform sample would be dominated by common types and might contain almost nothing from the segments most likely to fail. Sampling the auto-accepted pool is how an error rate in the high-confidence band is measured at all, because nobody reviews those items otherwise.
- Together these let limited reviewer capacity go to the cases that need it while keeping an ongoing check on the automated path.

### Trade-offs and alternatives

- **Per-field thresholds vs one global threshold:** per-field is more accurate and needs more labelled data and upkeep; a global threshold is simpler and over-accepts hard fields or over-reviews easy ones.
- **Higher accuracy target vs reviewer workload:** a stricter target routes more items to humans. Set it from the cost of an error, not from a round number.
- **Sample size per stratum:** larger samples give tighter error estimates and cost reviewer time; small strata may need all items sampled.
- **Labelled set freshness:** calibration decays as document mix or model version changes; recalibrate and keep sampling.
- **Self-reported confidence vs other signals:** self-reported scores are cheap but only useful once calibrated; agreement across independent passes or validation failures can supply additional routing signals.
- **Full review vs selective review:** full review is safest and does not scale; selective review scales but depends on the calibration being sound.

### Exam traps

- "97% overall accuracy, so automate extraction": aggregates mask segment failures. Rule: validate by document type and field before reducing human review.
- "Trust the model's confidence score as is": uncalibrated. Rule: calibrate thresholds on a labelled validation set.
- "Review a random sample of everything": wastes capacity on easy items and under-samples rare types. Rule: stratified sampling, plus targeted review of low-confidence and ambiguous items.
- "Stop reviewing once confidence is high": errors in the high-confidence band and new patterns go undetected. Rule: keep sampling auto-accepted output.
- "Use one threshold for all fields": fields differ in difficulty. Rule: calibrate per field.
- "Auto-accept when the model is confident even if sources disagree": confidence does not resolve contradictory inputs. Rule: route ambiguous or contradictory sources to humans.
